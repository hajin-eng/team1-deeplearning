## 3. 모델 파트가 해야 할 일 (우선순위 순)

`d["test_ids"]` 순서는 `제출_예시.csv`의 `shot_id` 순서와 같다는 것을 확인했습니다. 제출 규칙(상대경로, CPU, 10분 이내, 시드 고정, `제출_{팀명}.csv`)은 PDF에서 다시 확인하세요.

### 3-1. 모델 설계와 비교

1. **검증은 쌍둥이 그룹 분할로 합니다.** `analysis/common.py`의 `group_folds(y, groups)`를 그대로 쓰거나 같은 방식(`StratifiedGroupKFold`)을 옮기세요. `common.py`는 import하는 순간 `--quick` 인자 읽기와 출력 인코딩 변경이 적용되므로 `main.py`에서는 import하지 않는 것이 안전합니다. 랜덤 분할은 대조용으로만 쓰세요.
2. **모델 후보를 PyTorch MLP까지 확장해서 비교합니다.** 지금까지는 sklearn 모델 5종만 비교했습니다. PDF의 모델 요구사항(종류와 개수)은 PDF에서 다시 확인하세요.
3. **클래스 불균형 처리를 최종 모델에서 다시 비교합니다.** HGB 기본 설정으로 한 번 해 본 결과는 위 표에 있습니다. 확률 보정이 후보이고, 정상 헛경보율이 늘어나는 대가를 운영 기준과 함께 판단하세요. 오버샘플링은 쌍둥이를 늘려 검증을 오염시킬 수 있으니 반드시 학습 폴드 안에서만 하세요.
4. **환경 열 포함 / 제외를 모두 측정합니다.** 리더보드에는 포함 버전이 유리하지만 실제 성능은 다를 수 있습니다. 최종으로 어느 쪽을 쓸지는 보고서에 근거와 함께 적으세요.
5. **HGB 설정 후보를 정합니다.** B 설정이 후보이고, 전체 모드에서 다시 확인하세요 (전체 모드의 최고 설정 이름은 기록하지 않았습니다).
6. **제품별 모델과 앙상블은 사용하지 않습니다.** (진행하다가 문제가 있을 시 강사에게 다시 확인)
7. **Product_Type을 어떻게 쓸지 정합니다.** 현재는 열 그대로입니다. 제품별로 조건이 크게 다르고 불량 유형도 제품에 갈립니다 (Deformation·Exfoliation은 Type 1만, Blow_Hole은 Type 2만).
8. **스케일링은 모델 쪽에서 합니다.** 로지스틱·MLP는 `StandardScaler`를 파이프라인 안에 넣어 검증 폴드마다 학습 구간에만 맞추세요 (07번 참고).

## 4. 알아 둘 것

- **쌍둥이**: 입력이 같은 행이 42%입니다. 랜덤 분할로 점수를 재면 부풀려지고, test의 58%는 같은 입력이 train에 있어 리더보드도 부풀려질 수 있습니다. 이 구조는 test에도 있으므로 쌍둥이를 지우지 마세요.
- **불량이 시기·제품에 몰려 있습니다.** 시간순 검증은 검증 구간에 없는 클래스가 생겨서 "있는 클래스만 평균"해야 공정합니다. 시간순은 한 번뿐이라 노이즈가 큽니다 (로지스틱 한 모델도 조건에 따라 0.05~0.29로 흔들림, 07번).
- **점수 차이가 ±0.03보다 작으면 노이즈입니다.** 시드를 바꿔 다시 재서 확인하세요. HGB 설정 8가지 중 최고가 새 시드에서 거의 사라진 경험이 있습니다 (선택 편향).
- **`group` 번호는 검증 분할 전용입니다.** 특징에 넣으면 안 됩니다 (`load_data`가 `X_train`에 넣지 않습니다).
- **식별 열(shot_id, id, Shot)은 특징으로 쓰지 않고, 이웃 샷의 정답을 쓰면 실격입니다.** 쌍둥이의 라벨을 조회해서 예측하는 방법도 여기에 걸릴 수 있어 시도하지 않았습니다.
- **원본 불량 기록은 읽는 용도뿐입니다.** 특징·라벨로 쓰면 안 됩니다.
- **라벨 문자열 7종**: `정상`, `불량_Short_Shot`, `불량_Blow_Hole`, `불량_Exfoliation`, `불량_Deformation`, `불량_Stain`, `기타불량` (기타불량만 `불량_` 접두어가 없음). `y_train`은 문자열이라 PyTorch에서는 정수로 바꿔야 하고, 제출할 때 원래 문자열로 되돌리세요.
- **특징 25개** = 원본 21개 + 표시 열 4개(`is_restart`, `bad_biscuit`, `long_cycle`, `factory_missing`). 남은 결측은 0이라 따로 채울 필요가 없습니다.
- **열마다 크기가 많이 다릅니다.** 예: Casting_Pressure 516~1164, Velocity_1 0.1~0.2, Cycle_Time 20~219. 로지스틱·MLP는 스케일링이 필수입니다. 이상치 행의 극단값(Cycle_Time 최대 218.6 등)이 `StandardScaler`를 흔들 수 있으니 `RobustScaler`나 값 제한(clipping)도 비교해 보세요 (아직 비교하지 않았습니다).
- **환경(이 컴퓨터 기준)**: scikit-learn 1.9.0, torch 2.14.0(CPU)이 설치돼 있고 lightgbm·xgboost는 없습니다. 제출 환경의 라이브러리 규칙은 PDF에서 확인하세요.
- **재현성**: analysis의 모든 비교는 시드 0, 1, 2와 같은 폴드 분할로 측정했습니다. 새 모델도 같은 `group_folds`로 재야 위 표와 직접 비교할 수 있습니다.

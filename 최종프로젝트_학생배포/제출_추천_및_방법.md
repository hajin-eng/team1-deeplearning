# 중간(public) 제출 추천안과 방법 (2026-10-21)

팀장이 제출용 CSV를 만들 때 보는 문서입니다. 숫자는 `preprocess.py`의 `load_data()`로 만든 데이터에서 시드 0, 1 × 5조각으로 잰 평균이고, 근거 실험은 맨 아래에 있습니다.

## 1. 한 줄 추천

**전처리는 `preprocess.load_data()` 그대로, 모델은 HistGradientBoosting(HGB) 설정 B + `class_weight="balanced"`, 환경 열은 모두 유지.**

설정 B = `max_leaf_nodes=15, learning_rate=0.05, max_iter=100`

## 2. 왜 이 방식인가

| 특징 | 모델 | 그룹 분할 (실제 성능에 가까움) | 랜덤 분할 (쌍둥이로 부풀려짐) |
| --- | --- | --- | --- |
| 25개 전체 | 로지스틱 balanced (지금 main.py와 비슷) | 0.224 | 0.228 |
| 25개 전체 | HGB A (기본 설정) | 0.287 | 0.525 |
| 25개 전체 | **HGB B** | **0.308** | 0.402 |
| 환경 열 제외 | HGB B | 0.278 | 0.367 |

- 지금 main.py는 로지스틱이라 0.2517 기준선을 못 넘을 위험이 있습니다. HGB로 바꾸면 그룹 분할 기준 +0.08입니다.
- 환경 열을 빼면 모든 모델이 -0.03~-0.05라서 유지합니다.
- 설정 B가 A보다 그룹 분할 점수가 높고(0.308 vs 0.287) 표준편차도 작습니다(0.020 vs 0.031). 새 데이터에서의 성능이 더 믿을 만합니다.
- **주의:** test의 58%는 같은 입력이 train에 있습니다. 그래서 리더보드는 랜덤 분할 쪽에 가까워질 수 있고, 그러면 A가 리더보드에서는 더 높게 나올 수 있습니다 (어림으로 A 약 0.42, B 약 0.36, 정확한 값 아님). 그래도 B를 추천하는 이유는, 구술에서 "랜덤 분할 점수는 쌍둥이 때문에 부풀려졌다"고 설명할 수 있어야 하고, 모델 선택을 public 점수로 하면 안 되기 때문입니다.

## 3. main.py를 어떻게 고치나

main.py는 `preprocess.py`를 쓰지 않고 자체 전처리와 로지스틱을 씁니다. 바꿀 곳은 세 군데입니다 (아직 고치지 않았습니다).

1. **데이터 불러오기:** 위쪽에 `from preprocess import load_data`를 넣고, `load_data()`가 돌려주는 `X_train, y_train, groups_train, X_test, test_ids`를 씁니다.
   - `groups_train`은 검증 분할 전용이고 특징에 넣으면 안 됩니다.
   - `shot_id`, `id`, `Shot`은 특징에 들어가지 않습니다 (`load_data`가 이미 뺍니다).
2. **모델 교체:** `build_model()`의 Pipeline을 아래로 바꿉니다. HGB는 결측과 스케일링이 필요 없고, `load_data`의 결측은 이미 0개입니다.
   ```python
   from sklearn.ensemble import HistGradientBoostingClassifier

   HistGradientBoostingClassifier(
       class_weight="balanced",
       max_leaf_nodes=15,
       learning_rate=0.05,
       max_iter=100,
       random_state=SEED,
   )
   ```
   `make_class_weight`, `CLASS_WEIGHT_POWER`, `cross_validate()`의 `n_iter_` 출력은 쓰지 않으므로 지우거나 고칩니다.
3. **검증 분할:** `StratifiedGroupKFold(5, shuffle=True, random_state=SEED)`에 `groups_train`을 넣는 지금 방식을 유지합니다. 이 점수가 모델 선택 기준입니다.

그다음 `python main.py`로 `제출_동동문하.csv`를 만들고, 코드 안의 `check_submission()`이 형식 검사(2,261행, 열 이름 `shot_id,label`, 라벨 7종, `shot_id` 순서)를 통과하는지 봅니다. 규칙은 상대경로, CPU만, 10분 이내, 시드 고정(random, numpy, torch)입니다.

## 4. 제출할 때 주의

- 제출은 팀당 총 10회입니다. public 점수는 **참고용**이고, 모델 선택은 그룹 분할 CV 점수로 합니다.
- 추천안(설정 B)을 먼저 내고, 점수가 0.2517(공개 기준선)을 넘는지 확인합니다. 못 넘으면 리더보드에 등재되지 않습니다.
- 다른 설정(A 등)을 추가로 내 보는 것은 "그룹 점수와 리더보드 점수가 얼마나 다른지"를 보고서 6번(분할 비교)과 구술용으로 기록하려는 목적일 때만 하세요. 최종 모델을 public 점수 최고로 고르면 점수가 부풀려집니다.
- 점수 차이가 ±0.03보다 작으면 노이즈입니다.
- 쌍둥이의 라벨을 조회하는 방법, 이웃 샷의 정답을 쓰는 방법, 식별 열을 특징에 넣는 방법은 실격입니다.

## 5. 아직 확인하지 못한 것

- 설정 B는 시드 0, 1에서만 잰 값입니다. 이전에 8가지 중 최고가 새 시드에서 사라진 경험이 있으니 시드 2 이상으로 한 번 더 확인하면 좋습니다.
- PyTorch MLP, 학습곡선, 비교 실험 3종은 PDF가 요구하는 과제라서 별도로 해야 합니다 (`실험결과_및_할일.md` 3-1 참고).
- 경보 기준(확률 보정, 임계값)은 점수가 오르는 대신 헛경보가 늘어납니다. 운영안(보고서 7번)과 함께 따로 정하세요.

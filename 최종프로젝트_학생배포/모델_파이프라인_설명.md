# main.py 설명 (모델 파이프라인)

> 2026-10-22 기준 (현재 main.py = E안: RF 잎 최소 1·열 sqrt, 쌍둥이 분석·분할 비교 추가)
> 전처리는 데이터 파트 `preprocess.py`의 `load_data()`를 그대로 씁니다. `preprocess.py`는 수정하지 않고 main.py 쪽에서 받는 형식을 맞췄습니다(8절).

## 한 줄 요약

`python main.py`를 실행하면 **데이터를 읽어서 → 모델을 학습하고 → 검증 점수를 보여 준 뒤 → 제출 파일을 저장**합니다.

## 2. 전체 흐름 한눈에 보기

```
원본 CSV 3개 (입력 · 분할표 · 정답)
   ▼
[2~3단계] 데이터 파트 load_data()  → train 5,274행 / 제출 대상 2,261행, 피처 25개, 결측 채움, 쌍둥이 그룹 번호
   ▼         + main.py check_data()  → 행 수·식별 열·라벨 검사
   ▼
[4단계] 검증 방식 설계        → train 5,274행을 5조각으로 나눔 (학습용 약 4,219 / 검증용 약 1,055 쌍 × 5)
   ▼
[5단계] 학습 (5번 반복)       → 조각마다 나머지 4조각으로 새 모델을 학습하고, 남은 1조각을 예측
   ▼
[6단계] 평가                 → 5번의 검증 예측을 합쳐(train 전체) 한 번에 채점 (macro F1, 혼동행렬)
   ▼
[7단계] 제출                 → train 전체로 다시 학습 → 2,261행 예측 → 형식 검사 → 저장
```

**비유하면:** 기출문제(train)를 5묶음으로 나눕니다. 한 묶음을 모의고사(검증용)로 떼어 놓고 나머지로 공부(학습)하는 일을, 묶음을 바꿔 가며 5번 합니다. 그러면 기출문제 전체가 한 번씩 모의고사가 됩니다. 5번의 답안을 모아 실력을 확인(평가)한 다음, 기출문제 전체로 다시 공부해서 실전 시험(제출 대상)을 봅니다.

## 4. 함수별 역할 (쉬운 설명)

### `set_seed(seed)` — 결과를 매번 똑같이 만들기
컴퓨터의 "무작위"는 사실 시작 번호(시드)로 정해집니다. 시작 번호를 고정하면 몇 번을 돌려도 같은 결과가 나옵니다. 규칙상 필수입니다.

### `load_data(drop_cols=DROP_COLS)` — [2~3단계] 데이터 파트 전처리 (`preprocess.py`)
| 입력 | 출력 |
|---|---|
| 원본 CSV 3개 (`preprocess.py`가 직접 읽음) | 사전(dict): `X_train`, `y_train`, `groups_train`, `X_test`, `test_ids`, `feat` |

- 데이터 파트가 만든 함수를 그대로 불러옵니다(`from preprocess import load_data`). 자세한 처리는 `preprocess.py`와 `전처리_결정_정리.md`를 보세요.
- 받는 것: 피처 25개(공정 값 21개 + 표시 열 4개), 결측은 앞뒤 실측값 30개씩의 중앙값으로 채움, 식별 열은 이미 빠짐
- `groups_train`: 입력이 같은 쌍둥이 행끼리 같은 번호(3,663개). **검증 분할에만** 쓰고 피처에는 넣지 않습니다.
- 왜 쌍둥이 그룹이 필요한가: 쌍둥이 한쪽이 학습용, 다른 쪽이 검증용에 들어가면 모델이 **외워서 맞힙니다.** 검증 점수가 부풀려집니다.

### `check_data(data)` — [2~3단계] 받은 데이터 검사
| 입력 | 출력 |
|---|---|
| `load_data()`가 돌려준 사전 | 없음 (문제가 있으면 멈춤, 요약 한 줄 출력) |

- 행 수(5,274 / 2,261), train과 test의 열이 같은지, 식별 열(`shot_id`, `id`, `Shot`)과 그룹 번호가 피처에 없는지, 라벨이 7종 안인지 확인합니다.
- `load_data`의 옵션이 바뀌어도 실격 조건을 바로 잡아내려고 받는 쪽에서 한 번 더 확인합니다.

### `split_validation(y, groups)` — [4단계] 5조각으로 나누기
| 입력 | 출력 |
|---|---|
| train 정답 `y_train`, 쌍둥이 그룹 번호 `groups_train` | (학습용 행 번호, 검증용 행 번호) 쌍 5개의 리스트 `folds` |

- train 5,274행을 5조각으로 나누고, **각 조각이 한 번씩 검증용**이 되도록 5쌍을 만듭니다. 두 가지 조건을 지킵니다.
  - **쌍둥이는 같은 조각에** (Group)
  - **불량 종류별 비율은 조각마다 같게** (Stratified). 기타불량처럼 적은 클래스가 한 조각에 몰리지 않도록
- `StratifiedGroupKFold`라는 sklearn 도구를 씁니다. 쌍둥이 그룹을 쪼갤 수 없는 덩어리로 보고, 덩어리마다 클래스 비율이 가장 고르게 되는 조각에 넣습니다.
- 출력은 데이터가 아니라 **행 번호 명단**입니다.
- 모든 train 행이 **정확히 한 번씩** 검증용이 되었는지 자동으로 검사합니다.

### `cross_validate(X, y, folds)` — [5～6단계] 5번 학습하고 예측 모으기
| 입력 | 출력 |
|---|---|
| train 피처 `X_train`, 정답 `y_train`, 5쌍 `folds` | train 5,274행마다 검증 예측 1개씩(`oof_pred`), 조각별 macro F1 5개 |

- 조각마다 **새 모델**을 만들어 학습용으로 학습하고, 검증용을 예측합니다. 모델을 만들 때 **그 조각의 학습용 정답**(`y_fit`)을 넘겨 class_weight를 계산합니다.
- 검증 예측을 빈 답안지의 해당 칸에 채워 넣습니다. 5번 돌면 train 전체가 채워집니다. 이렇게 "그 행을 학습에 쓰지 않은 모델이 낸 예측"을 **oof(out-of-fold) 예측**이라고 합니다.
- 조각별 점수와 평균 ± 표준편차를 출력합니다. 표준편차는 점수가 분할 운에 얼마나 흔들리는지 보여 줍니다.
- **왜 한 번만 나누지 않나:** 검증용 1,055행에는 소수 클래스가 15～20개뿐이라, 어떤 샷이 검증용에 들어가느냐에 따라 점수가 달라집니다. 실제로 한 번 나누기로 쓰던 0.239는 5조각 중 가장 높은 조각의 점수였습니다.

### `make_class_weight(y)` — [5단계] 클래스별 가중치 계산
| 입력 | 출력 |
|---|---|
| 학습용 정답 | `{클래스: 가중치}` 사전 |

- 먼저 sklearn의 balanced 가중치를 계산합니다: `전체 샷 수 ÷ (클래스 수 × 그 클래스 샷 수)`. 적은 클래스일수록 가중치가 큽니다.
- 그 값에 **강도**(`CLASS_WEIGHT_POWER`)를 거듭제곱합니다. 지금은 0.5, 즉 balanced의 제곱근입니다.

| 클래스 (train 전체 기준) | 샷 수 | balanced (강도 1) | **강도 0.5 (현재)** |
|---|---|---|---|
| 정상 | 4,092 | 0.184 | 0.429 |
| 불량_Short_Shot | 469 | 1.606 | 1.267 |
| 불량_Blow_Hole | 233 | 3.234 | 1.798 |
| 불량_Exfoliation | 198 | 3.805 | 1.951 |
| 불량_Deformation | 106 | 7.108 | 2.666 |
| 불량_Stain | 100 | 7.534 | 2.745 |
| 기타불량 | 76 | 9.914 | 3.149 |
| **기타불량 ÷ 정상** | | **54배** | **7.3배** |

- **왜 balanced 그대로 쓰지 않나:** balanced는 기타불량 1개를 정상 1개의 54배로 취급해서, 모델이 "애매하면 불량"을 배웁니다. 그 결과 정상의 77%를 불량이라고 불렀습니다. 강도를 0.5로 낮추면 차이가 7.3배로 줄어듭니다.
- **학습용 정답만으로 계산하는 이유:** 검증용 정답까지 세면 검증 정보가 새어 들어갑니다. 그래서 교차검증 조각마다 그 조각의 학습용 정답으로 따로 계산합니다.

### `build_model(y)` — [5단계] 모델 만들기
| 입력 | 출력 |
|---|---|
| 학습용 정답 (class_weight 계산용) | 아직 학습하지 않은 모델 |

설정 영역의 `MODEL_NAME`에 따라 세 모델 중 하나를 **Pipeline**으로 묶어 만듭니다. 지금은 `"rf"`입니다.

```
"rf"       : 결측 채우기 (중앙값)  →  랜덤포레스트 (나무 300그루, 잎 최소 1, 질문마다 열 sqrt)
"logistic" : 결측 채우기 (중앙값)  →  크기 맞추기 (StandardScaler)  →  로지스틱 회귀
"hgb"      : HistGradientBoosting (데이터 파트 추천 설정 B: 잎 최대 15, 학습률 0.05, 나무 100)
```
- rf와 logistic은 `class_weight = make_class_weight(y)`(강도 적용)를 씁니다.
- hgb는 글자 라벨로 만든 가중치 사전을 받지 못해서(sklearn이 내부에서 라벨을 숫자로 바꾼 뒤 찾음) 데이터 파트 추천 그대로 `class_weight="balanced"`를 씁니다.
- `MODEL_NAME`에 다른 글자가 들어가면 오류를 내고 멈춥니다.
- 결측 채우기는 지금 결측이 0개라 아무 일도 하지 않지만, `load_data`의 채우기 방식이 바뀌어도 안전하도록 남겨 두었습니다.

- **결측 채우기·크기 맞추기를 모델 안에 넣은 이유:** 중앙값이나 평균은 **학습용 데이터에서만** 계산해야 합니다. 검증용·제출 대상까지 섞어서 계산하면 정보가 새어 나갑니다. Pipeline에 넣으면 `fit`할 때 계산하고, `predict`할 때는 계산해 둔 값을 쓰기만 해서 자동으로 지켜집니다.
- **크기 맞추기 (로지스틱만):** 주조압(약 859)과 속도(약 0.15)처럼 크기가 다른 값을 비슷한 크기로 맞춥니다. 로지스틱 회귀는 이것이 없으면 학습이 잘 끝나지 않습니다. 랜덤포레스트는 "367보다 큰가?"처럼 크고 작음만 보기 때문에 필요 없습니다.
- **랜덤포레스트:** 질문으로 샷을 나누는 나무(스무고개)를 서로 조금씩 다른 데이터로 300그루 키워서 다수결로 답합니다. 로지스틱(직선)과 달리 "A가 367 이하**이고** B가 54 이하면" 같은 조건 조합을 쓸 수 있습니다.
- **잎 최소 1 (`RF_MIN_LEAF`):** 나무 끝(잎)에 샷이 최소 1개만 있어도 결론을 냅니다. 샷 하나하나까지 쪼개서 사실상 학습 데이터를 외웁니다(학습용 F1 0.97 vs 검증 0.29). E안 설정이고, 쌍둥이를 가장 잘 알아봅니다. 값이 클수록 덜 외웁니다(자세한 비교는 6절).
- **열 `sqrt` (`RF_MAX_FEATURES`):** 질문 하나를 고를 때 25개 열 중 5개만 무작위로 보여 줍니다. `0.5`면 12개를 봅니다(많이 볼수록 더 외움).
- **class_weight:** 정상이 77%라서, 그냥 학습하면 모델이 전부 "정상"이라고 답합니다. 적은 불량을 틀리면 벌점을 크게 줘서 불량도 찾게 만듭니다. 가중치는 위의 `make_class_weight(y)`가 계산합니다.
- 📌 **모델을 추가할 때(MLP 등)는 이 함수에 `elif MODEL_NAME == "..."` 칸만 더하면 됩니다.** 나머지 코드는 그대로 씁니다.

### `evaluate(y_true, y_pred)` — [6단계] 채점하기
| 입력 | 출력 |
|---|---|
| train 5,274행의 정답, 합친 검증 예측(`oof_pred`) | macro F1 점수 (화면에 성적표와 혼동행렬도 출력) |

- **합쳐서 한 번 채점하는 이유:** 조각마다 따로 채점하면 소수 클래스가 3～5개씩이라 F1이 크게 튑니다. 합치면 클래스마다 76～469개가 모여 안정적이고, 혼동행렬도 하나로 볼 수 있습니다.
- **macro F1:** 대회 채점 기준. 7종 각각의 F1을 단순 평균
- **클래스별 성적표:** 종류마다 precision(헛경보가 적은가), recall(놓치지 않는가)
- **혼동행렬:** 무엇을 무엇으로 착각했는지 보여 주는 7×7 표 (행 = 실제, 열 = 예측)

### `make_submission(model, X_test, test_ids)` — [7단계] 제출 표 만들기
| 입력 | 출력 |
|---|---|
| 학습된 모델, 제출 대상 2,261행의 피처, 그 행들의 shot_id | `shot_id, label` 두 열짜리 표 |

- shot_id는 표에 이름표로만 붙이고, 모델에는 넣지 않습니다.

### `check_submission(sub)` — [7단계] 실격 조건 검사
저장하기 **전에** 아래 네 가지를 확인합니다. 하나라도 틀리면 멈춥니다.
1. 행 수가 2,261인가
2. 열 이름이 정확히 `shot_id, label`인가
3. shot_id가 `제출_예시.csv`와 같은 순서로 같은가
4. 라벨이 허용된 7종 안에만 있는가

### `main()` — 전체 순서대로 실행
위 함수들을 2단계부터 7단계까지 순서대로 부릅니다. 교차검증의 5개 모델은 점수를 재는 데만 쓰고, 7단계에서는 **train 전체(5,274행)로 새 모델을 다시 학습**해서 제출 파일을 만듭니다.

## 5. 무엇을 바꾸고 싶을 때 어디를 고치나

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 특정 열을 빼고 돌려 보기 | 설정 영역 `DROP_COLS = ("열이름",)` → `load_data(drop_cols=...)`로 넘어갑니다. 환경 열 전체는 `preprocess.ENV_COLS` |
| class_weight 강도 바꾸기 | 설정 영역 `CLASS_WEIGHT_POWER` (지금 0.5. 0 = 끔, 1 = balanced 그대로) |
| 여러 강도를 한 번에 비교하기 | `python 실험_class_weight.py` (아래 6절) |
| 모델 바꾸기 | 설정 영역 `MODEL_NAME` (`"rf"`, `"logistic"`, `"hgb"`, `"rf_et"` = RF와 ExtraTrees 확률 평균(F안), `"rf_et_2stage"` = F안과 두 단계 모델 혼합(G안), 나무 수는 `RFET_N_TREES`) |
| HGB 설정 바꾸기 | 설정 영역 `HGB_MAX_LEAF_NODES`, `HGB_LEARNING_RATE`, `HGB_MAX_ITER` |
| 모델 3종을 여러 시드로 비교하기 | `python 실험_모델비교.py` (아래 6절) |
| RF 설정 바꾸기 | 설정 영역 `RF_N_TREES` (지금 300), `RF_MIN_LEAF` (지금 1), `RF_MAX_FEATURES` (지금 `"sqrt"`) |
| RF 잎 최소 × 강도를 한 번에 비교하기 | `python 실험_RF.py` (아래 6절) |
| 새 모델 추가하기 (MLP 등) | `build_model()`에 `elif` 칸 추가 |
| 전처리 방식 바꾸기 | 데이터 파트 `preprocess.py` (담당: 데이터 파트). main.py는 `load_data()`를 부르기만 합니다 |
| 교차검증 조각 수 바꾸기 | 설정 영역 `VALID_FOLDS` (지금 5) |
| 쌍둥이 그룹 기준 | 데이터 파트 `preprocess.py`의 `make_groups()` (교차검증 코드는 그대로) |

| **RF 잎 5** | 0.324 | 0.448 | 0.471 |

### class_weight 강도 실험 (`실험_class_weight.py`, 로지스틱 기준)
`main.py`를 불러와서 `CLASS_WEIGHT_POWER`만 바꿔 끼우며 교차검증을 반복합니다. 제출 파일은 만들지 않습니다. 아래 표는 로지스틱일 때 결과이고, 지금 실행하면 `MODEL_NAME`에 설정된 모델(RF)로 돕니다.

| 강도 | 합쳐서 macro F1 | 조각 평균 ± 표준편차 | 정상 recall |
|---|---|---|---|
| 0 (끔) | 0.1258 | 0.1258 ± 0.0023 | 0.996 |
| 0.25 | 0.2047 | 0.2028 ± 0.0294 | 0.955 |
| **0.5 (선택)** | **0.2896** | 0.2896 ± 0.0088 | 0.791 |
| 0.6 | 0.2895 | 0.2897 ± 0.0054 | 0.688 |
| 0.75 | 0.2760 | 0.2773 ± 0.0205 | 0.487 |
| 1 (balanced) | 0.2255 | 0.2261 ± 0.0092 | 0.235 |

- 너무 약하면 전부 "정상", 너무 세면 전부 "불량"이라서 중간이 가장 좋습니다.
- 0.5와 0.6은 차이(0.0001)가 흔들림(±0.005～0.009)보다 훨씬 작아서 **점수로는 같습니다.**
- 0.6은 불량이라고 더 자주 말합니다. 유형까지 맞힌 불량이 약 72개 늘지만, 불량이라고 잘못 부른 정상도 약 422개 늘어납니다.
- **0.5를 고른 이유:** 점수가 같으면 헛경보(정상을 불량이라고 부르기)가 적은 쪽이 현장 재검사 부담이 작기 때문입니다. "불량을 놓치는 것이 더 비싸다"는 운영 방향이라면 0.6도 타당합니다.
- 모델을 바꾸면(RF, MLP) 가장 좋은 강도가 달라질 수 있어서, 그때 이 실험을 다시 돌립니다.

# main.py 설명 (모델 파이프라인)

> 작성: 김동언 (모델 파트) · 2026-10-19 기준 (검증을 5조각 교차검증으로 변경)
> 모델 파이프라인이 처음부터 끝까지 돌아가는지 확인하려고 만든 **첫 버전**입니다. 전처리는 임시 방식이며, 데이터 파트(`preprocess.py`) 결과를 반영해서 바꿀 예정입니다(8절).

## 한 줄 요약

`python main.py`를 실행하면 **데이터를 읽어서 → 모델을 학습하고 → 검증 점수를 보여 준 뒤 → 제출 파일(`제출_동동문하.csv`)을 저장**합니다.

## 2. 전체 흐름 한눈에 보기

```
원본 CSV 3개 (입력 · 분할표 · 정답)
   ▼
[2단계] 데이터 불러오기      → 하나의 표로 합침 (7,535행)
   ▼
[3단계] 전처리               → 모델에 넣을 피처 21개만 남김
   ▼
[4단계] 검증 방식 설계        → train 5,274행을 5조각으로 나눔 (학습용 약 4,219 / 검증용 약 1,055 쌍 × 5)
   ▼
[5단계] 학습 (5번 반복)       → 조각마다 나머지 4조각으로 새 모델을 학습하고, 남은 1조각을 예측
   ▼
[6단계] 평가                 → 5번의 검증 예측을 합쳐(train 전체) 한 번에 채점 (macro F1, 혼동행렬)
   ▼
[7단계] 제출                 → train 전체로 다시 학습 → 2,261행 예측 → 형식 검사 → 저장
```

**비유하면:** 기출문제(train)를 5묶음으로 나눕니다. 한 묶음을 모의고사(검증용)로 떼어 놓고 나머지로 공부(학습)하는 일을, 묶음을 바꿔 가며 5번 합니다. 그러면 기출문제 전체가 한 번씩 모의고사가 됩니다. 5번의 답안을 모아 실력을 확인(평가)한 다음, 기출문제 전체로 다시 공부해서 실전 시험(제출 대상)을 봅니다.

## 4. 함수별 역할 (쉬운 설명)

### `set_seed(seed)` — 결과를 매번 똑같이 만들기
컴퓨터의 "무작위"는 사실 시작 번호(시드)로 정해집니다. 시작 번호를 고정하면 몇 번을 돌려도 같은 결과가 나옵니다. 규칙상 필수입니다.

### `load_data()` — [2단계] 파일 3개를 하나의 표로 합치기
| 입력 | 출력 |
|---|---|
| `data/주조공정_입력.csv`, `분할표.csv`, `정답_train.csv` | 7,535행짜리 표 하나 (`df`) |

- 세 파일을 `shot_id` 기준으로 붙입니다. 각 샷마다 "공정 값 + train인지 아닌지 + 정답(train만)"이 한 줄에 모입니다.
- 생산 순서대로(`shot_id` 순) 정렬합니다.
- 행 수, 정답 유무, 라벨 이름이 맞는지 **자동으로 검사**합니다. 하나라도 틀리면 그 자리에서 멈추고 이유를 알려 줍니다.

### `preprocess(df)` — [3단계] 모델에 넣을 열만 남기기
| 입력 | 출력 |
|---|---|
| 합친 표 `df` | 피처 표 `X` (7,535행 × 21열) |

- 빼는 열:
  - **식별 열** `shot_id`, `id`, `Shot`: 규칙상 피처로 쓰면 실격
  - **정답·분할 열** `label`, `split`: 문제에 답을 같이 주면 안 되므로
  - **상수 열 8개** (`Air_Pressure_Min` 등): 모든 행에서 값이 하나뿐이라 정보가 없음
- **행은 건드리지 않습니다.** 열만 뺍니다. 그래야 `X`와 `df`의 행 순서가 같게 유지됩니다.
- 결측 채우기는 여기서 하지 않습니다. 5단계 모델 안에서 합니다(이유는 5단계 설명 참고).
- 📌 **데이터 파트 결과가 들어올 자리입니다.**

### `make_twin_groups(df)` — [4단계] 쌍둥이 행 찾기
| 입력 | 출력 |
|---|---|
| 합친 표 `df` | 행마다 그룹 번호 (7,535개) |

- 이 데이터에는 **같은 샷이 두 번 기록된 행**(바로 앞 행과 Shot까지 모든 입력값이 같은 행)이 2,918개 있습니다.
- 바로 앞 행과 같으면 같은 번호, 다르면 새 번호를 붙입니다. 결과적으로 그룹이 4,617개 생깁니다.
- 왜 필요한가: 쌍둥이 한쪽이 학습용, 다른 쪽이 검증용에 들어가면 모델이 **외워서 맞힙니다.** 검증 점수가 부풀려집니다(RF 기준 0.455 → 실제 0.274).

### `split_validation(df, groups)` — [4단계] 5조각으로 나누기
| 입력 | 출력 |
|---|---|
| 합친 표 `df`, 그룹 번호 | (학습용 행 번호, 검증용 행 번호) 쌍 5개의 리스트 `folds` |

- train 5,274행을 5조각으로 나누고, **각 조각이 한 번씩 검증용**이 되도록 5쌍을 만듭니다. 두 가지 조건을 지킵니다.
  - **쌍둥이는 같은 조각에** (Group)
  - **불량 종류별 비율은 조각마다 같게** (Stratified). 기타불량처럼 적은 클래스가 한 조각에 몰리지 않도록
- `StratifiedGroupKFold`라는 sklearn 도구를 씁니다. 쌍둥이 그룹을 쪼갤 수 없는 덩어리로 보고, 덩어리마다 클래스 비율이 가장 고르게 되는 조각에 넣습니다.
- 출력은 데이터가 아니라 **행 번호 명단**입니다.
- 모든 train 행이 **정확히 한 번씩** 검증용이 되었는지 자동으로 검사합니다.

### `cross_validate(df, X, folds)` — [5～6단계] 5번 학습하고 예측 모으기
| 입력 | 출력 |
|---|---|
| 합친 표 `df`, 피처 표 `X`, 5쌍 `folds` | train 5,274행마다 검증 예측 1개씩(`oof_pred`), 조각별 macro F1 5개 |

- 조각마다 **새 모델**을 만들어 학습용으로 학습하고, 검증용을 예측합니다.
- 검증 예측을 빈 답안지의 해당 칸에 채워 넣습니다. 5번 돌면 train 전체가 채워집니다. 이렇게 "그 행을 학습에 쓰지 않은 모델이 낸 예측"을 **oof(out-of-fold) 예측**이라고 합니다.
- 조각별 점수와 평균 ± 표준편차를 출력합니다. 표준편차는 점수가 분할 운에 얼마나 흔들리는지 보여 줍니다.
- **왜 한 번만 나누지 않나:** 검증용 1,055행에는 소수 클래스가 15～20개뿐이라, 어떤 샷이 검증용에 들어가느냐에 따라 점수가 달라집니다. 실제로 한 번 나누기로 쓰던 0.239는 5조각 중 가장 높은 조각의 점수였습니다.

### `build_model()` — [5단계] 모델 만들기
| 입력 | 출력 |
|---|---|
| 없음 | 아직 학습하지 않은 모델 |

모델은 세 단계를 하나로 묶은 **Pipeline**입니다.

```
결측 채우기 (중앙값)  →  크기 맞추기 (StandardScaler)  →  로지스틱 회귀 (class_weight="balanced")
```

- **결측 채우기·크기 맞추기를 모델 안에 넣은 이유:** 중앙값이나 평균은 **학습용 데이터에서만** 계산해야 합니다. 검증용·제출 대상까지 섞어서 계산하면 정보가 새어 나갑니다. Pipeline에 넣으면 `fit`할 때 계산하고, `predict`할 때는 계산해 둔 값을 쓰기만 해서 자동으로 지켜집니다.
- **크기 맞추기:** 주조압(약 859)과 속도(약 0.15)처럼 크기가 다른 값을 비슷한 크기로 맞춥니다. 로지스틱 회귀는 이것이 없으면 학습이 잘 끝나지 않습니다.
- **class_weight="balanced":** 정상이 77%라서, 그냥 학습하면 모델이 전부 "정상"이라고 답합니다. 적은 불량을 틀리면 벌점을 크게 줘서 불량도 찾게 만듭니다.
- 📌 **모델을 바꿀 때(RF, MLP)는 이 함수 안만 바꾸면 됩니다.** 나머지 코드는 그대로 씁니다.

### `evaluate(y_true, y_pred)` — [6단계] 채점하기
| 입력 | 출력 |
|---|---|
| train 5,274행의 정답, 합친 검증 예측(`oof_pred`) | macro F1 점수 (화면에 성적표와 혼동행렬도 출력) |

- **합쳐서 한 번 채점하는 이유:** 조각마다 따로 채점하면 소수 클래스가 3～5개씩이라 F1이 크게 튑니다. 합치면 클래스마다 76～469개가 모여 안정적이고, 혼동행렬도 하나로 볼 수 있습니다.
- **macro F1:** 대회 채점 기준. 7종 각각의 F1을 단순 평균
- **클래스별 성적표:** 종류마다 precision(헛경보가 적은가), recall(놓치지 않는가)
- **혼동행렬:** 무엇을 무엇으로 착각했는지 보여 주는 7×7 표 (행 = 실제, 열 = 예측)

### `make_submission(model, X_test, test_ids)` — [7단계] 제출 표 만들기
| 입력 | 출력 |
|---|---|
| 학습된 모델, 제출 대상 2,261행의 피처, 그 행들의 shot_id | `shot_id, label` 두 열짜리 표 |

- shot_id는 표에 이름표로만 붙이고, 모델에는 넣지 않습니다.

### `check_submission(sub)` — [7단계] 실격 조건 검사
저장하기 **전에** 아래 네 가지를 확인합니다. 하나라도 틀리면 멈춥니다.
1. 행 수가 2,261인가
2. 열 이름이 정확히 `shot_id, label`인가
3. shot_id가 `제출_예시.csv`와 같은 순서로 같은가
4. 라벨이 허용된 7종 안에만 있는가

### `main()` — 전체 순서대로 실행
위 함수들을 2단계부터 7단계까지 순서대로 부릅니다. 교차검증의 5개 모델은 점수를 재는 데만 쓰고, 7단계에서는 **train 전체(5,274행)로 새 모델을 다시 학습**해서 제출 파일을 만듭니다.

## 8. 데이터 파트 결과 반영 예정
처음에는 데이터 파트와 모델 파트를 동시에 진행해야 했습니다. 그래서 모델 파이프라인을 먼저 끝까지 돌려 보려고, 전처리 부분은 **임시로 가장 단순한 방식**을 넣어 두었습니다.
전처리는 데이터 파트 담당이므로, 앞으로 **데이터 파트(`preprocess.py`)의 결정을 기준으로 main.py를 바꿔 나갈 예정**입니다.

| 항목 | 지금 main.py (임시) | 반영할 데이터 파트 결정 |
|---|---|---|
| 데이터 읽기·전처리 | main.py 안에서 직접 처리 | `preprocess.py`의 함수를 불러와서 사용 |
| 결측 채우기 | 중앙값 | 결측 구간 앞뒤 실측값 30개씩의 중앙값 |
| 중복 행 그룹 (검증 분할용) | 바로 앞 행과 같은 행 기준 | `preprocess.py`의 그룹 번호 사용 |
| 표시 열·환경 열 | 사용 안 함 | 데이터 파트 정리(`전처리_결정_정리.md`)에 따라 반영 |

연결하는 방법(어떤 함수를 불러와서 무엇을 받을지)은 데이터 파트 담당에게 설명을 듣고 그에 맞춰 진행하겠습니다.

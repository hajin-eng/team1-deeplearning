# 구술 Q&A 예상 질문과 답변 초안 (발표자용)

- 방식: 공식 질문 13개 중 **무작위 3개 + 현장 수정 1개**(5분)가 나간다. "AI가 그렇게 해서"는 0점, 모르면 "모릅니다"가 정답.
- 규칙: 숫자에는 **단위와 분모**를 붙인다("0.68" ❌ / "불량 100건 중 68건" ✅). 한계는 숨기지 말고 **숫자 → 이유 → 다음에 할 일** 순서로 말한다. "앞으로 개선하겠습니다"는 쓰지 않는다.
- 이름: **1안 = 최종 제출안**(코드의 H안), **2안 = 현장성을 높인 또 다른 안**(팀원 폴더의 D안).
- 숫자 출처: 보고서 PDF의 표, `최종_정리.md`. 아래 숫자는 모두 학습 데이터 검증 값이고(별도 표기 제외), 시드 흔들림 때문에 소수점 끝자리는 자료마다 조금 다를 수 있다.

## A. 공식 질문 13개 (답 초안)

### 1. 데이터를 어떤 순서로 점검했습니까? 각 단계에서 무엇을 확인했습니까?
1. **열 확인**: 32열 중 식별 열(shot_id·id·Shot) 3개, 값이 하나뿐인 Min/Max 상수 열 8개를 찾았다.
2. **중복 구조**: 입력 21개가 바로 앞 행과 같은 행이 3,174개(42%)이고, 같은 묶음 안 라벨이 97.8% 같았다(쌍둥이).
3. **불량 기록 구조**: 원본 불량 기록과 정답을 대조해 7종으로 접힌 방식을 읽었다.
4. **결측·이상값**: 공장 온도·습도 90행이 두 덩어리로 비어 있었고, 속도 0·긴 사이클·이상치 15행이 있었다.
5. **교란**: shot 4208에서 제품 유형이 바뀌고, 불량 종류가 제품·시기에 몰린다(400샷 구간 불량률 1.8~51%).

### 2. 가장 중요한 문제는 무엇이고 어떻게 처리했습니까?
- **쌍둥이(중복 행)**. 시험 데이터의 약 58%도 같은 구조라서 점수가 "같은 입력을 외우는 능력"에 크게 좌우된다.
- 행은 지우지 않고, 묶음 번호를 **검증 분할에만** 썼다(특징으로는 안 씀). 그래서 검증을 "같은 입력이 학습에 있는 샷"과 "없는 샷(새 입력)"으로 나눠 본다.

### 3. 버린 열이 몇 개고 무슨 기준이었습니까?
- **11개**: 식별 열 3개(규칙상 특징으로 쓸 수 없음) + 값이 하나뿐인 상수 열 8개(정보 없음). 32열 → 21열, 여기에 표시 열 4개(속도 0, 두께 0, 긴 사이클, 공장 결측)를 더해 25개를 입력으로 썼다.

### 4. 이상하다고 판단한 값이 있었습니까? 기준과 처리는?
- **속도 0·긴 사이클**: 설비 정지로 보인다. 지우지 않고 표시 열만 추가했다. 지워도 점수 차가 표준편차 안쪽이었다.
- **공장 온도·습도 결측 90행**: 전부 제품 유형 2, 두 덩어리. 앞뒤 실측 30개씩의 중앙값으로 채우고 결측 표시 열을 남겼다(방식·창 크기에 따른 점수 차 0.004).
- **이상치 15행**: 지우지 않고 유지(점수 차가 표준편차 안쪽).

### 5. 학습곡선이 어떤 모양입니까? 그래서 현장에 뭘 제안하겠습니까?
- **epoch 곡선**: 학습 손실은 계속 내려가지만 검증 손실은 epoch 18(1.143)에서 최저, epoch 60에서 1.188(+4%). "epoch 18부터 외우기 시작"한다.
- **데이터양 곡선**: 학습 데이터를 20→100%로 늘리면 새 입력 점수는 0.193→0.253이고 60% 이후 평평하다. 이미 본 조건의 점수는 오르지만 새 조건은 거의 안 오른다.
- **제안**: 데이터를 더 모으기보다 **불량과 정상을 가르는 새 측정**을 찾는 것이 먼저다(가정 기반 계산: 구분력이 표준편차의 약 1배 이상인 측정이어야 의미가 있음, 실제 결과 아님).

### 6. 무작위 분할과 시간순 분할 점수가 얼마나 달랐습니까? 어느 쪽이 배포 성능입니까?
- 1안: **무작위 0.560 → 쌍둥이 묶음 0.256 → 시간순 0.125**(시간순 탐지 0%). 2안: 0.504 → 0.338 → 0.111.
- **배포 성능에 가까운 것은 시간순**이다. 무작위는 같은 입력이 학습에 섞여 들어가 부풀려진다. 다만 시간순 구간은 전부 제품 유형 2이고 학습에 이 제품이 1,269행뿐이라 "새 시기의 같은 제품"을 거의 못 본 시험이다.

### 7. 왜 그 모델을 최종으로 골랐습니까? 2등 모델과 뭐가 달랐습니까?
- **정직하게**: 최종 제출 모델은 **중간 리더보드 점수(1안 0.5987, 2안 0.5710)를 기준**으로 1안으로 정했다. 그리고 검증으로도 같은 방향을 확인했다.
  - 시험 구조(쌍둥이 58.4%)대로 가중한 내부 검증 점수가 1안 약 0.62, 2안 약 0.55(어림값, 실제와 ±0.02 차이)로 1안이 높았다.
- **2안과의 차이**: 1안은 같은 입력을 외우고 앞뒤 입력까지 쓴다. 2안은 입력 25개·숲 2개로 불량을 더 적극적으로 부른다. 새 입력에서 불량 탐지가 **1안 10.3% 대 2안 48.0%**, 새 생산 구간에서 **1.2% 대 31.0%**다. 대신 정상 4,092건 중 헛경보가 1안 73건, 2안 749건이다.
- 그래서 제출 CSV는 1안, 현장 운영에서 실시간 판정이 필요하면 2안이다. 1안은 뒤 사건 입력이 필요해 사후 분석용이다.
- 주의: "public이 높아서"만 말하면 감점이다. 위처럼 **검증 근거와 한계를 같이** 말한다.

### 8. 임계값(또는 class_weight)을 어떻게 정했습니까? 바꾸면 뭐가 달라집니까?
- **class_weight**: balanced 가중치의 **0.5제곱**. 0.3 / 0.75 / 1.0과 비교한 점수 차가 −0.0002 / +0.0006 / −0.0007로 노이즈라 0.5를 유지했다. 강하게 줄수록 탐지는 늘지만 헛경보도 늘어 점수는 그대로다.
- **경보 기준(정상 확률 배율)**: 낮출수록 불량으로 더 자주 부른다. 하루 3,800샷 기준 ×1.0이면 검사 154샷·놓침 759·헛경보 61, ×0.1이면 검사 2,575샷·놓침 87·헛경보 1,810이다.

### 9. 중간 점수와 최종 점수가 다르다면 왜 그렇습니까?
- 시험 샷이 public 1,130 / private 1,131개뿐이라 **표본만으로 점수가 SD 약 0.037 흔들린다**. 시험 샷 중 쌍둥이 비율도 private 58.4%, public 57.1%로 다르다.
- 내부 어림값은 실제보다 높게 나왔다(1안: 어림 0.623, 실제 public 0.5987). 그래서 **점수 예측은 하지 않는다**.

### 10. 이 모델을 내일 현장에 걸면 하루에 헛경보가 몇 번 납니까?
- 하루 3,800샷 가정(사이클 시간 중앙값 22.6초, 24시간 가동; 8시간 교대면 약 1,270샷). 새 입력 기준:
  - **기준 ×1.0**: 헛경보 약 61건, 놓침 약 759건(불량 약 850건 중).
  - **운영안 ×0.1**: 헛경보 1,810건, 놓침 87건, 검사 대상 2,575샷(전체의 68%).
- **"비용 비율은 현장이 정해 주셔야 합니다."** 놓침 1건 = 헛경보 5·10·20건으로 표를 만들어 두었고, 웹 보고서의 계산기에 현장 비율을 넣으면 바로 최저 기준이 나온다(10:1에서 전수 검사 대비 약 9~15% 절감, 20:1에서는 이점 없음).

### 11. 찾아낸 불량 조건이 정말 원인이라고 말할 수 있습니까? 어떻게 확인하겠습니까?
- **"말할 수 없습니다. 상관입니다."** 예: 유형 2 제품에서 High_Velocity > 2.537이면 Short_Shot 5.3%(밖 15.8%), Blow_Hole 0.7%(밖 12.3%).
- 이유: 구간 경계를 같은 데이터에서 골랐고, 속도가 높은 샷은 금형 온도·시기·설비 상태와 같이 움직였을 수 있다. High_Velocity는 몇 개 값 덩어리로 뭉쳐 설정 묶음의 표지일 수 있다.
- **확인 방법**: 그 변수만 구간 안팎으로 바꿔 시험 생산(A/B)하고, 같은 제품·같은 시기에서 불량률을 비교한다. 그 전까지는 "관리 후보"다.

### 12. 운영안을 public 점수가 아니라 무엇으로 정했습니까? 왜 그래야 합니까?
- **학습 데이터 안에서 떼어 둔 검증**(새 입력 5분할, 시드 평균)으로 비용표를 만들었다. public은 쓰지 않았다.
- 이유: public 점수는 시험 샷 1,130개뿐이라 흔들림이 크고, 같은 입력이 학습에 있는 샷이 많아(약 57%) 현장 새 샷의 성능을 대표하지 못한다. 운영안은 **현장 새 샷에서의 놓침·헛경보 건수**로 정해야 한다.
- 제출 CSV(점수용, ×1.0)와 운영안(×0.1)이 다른 이유도 같다: CSV는 macro F1을 높이는 7종 분류, 운영안은 놓침 비용을 반영해 더 자주 경보를 낸다.

### 13. 라벨 7종은 어떻게 정해졌다고 봅니까? 기타불량에는 무엇이 들어 있겠습니까? 모델·운영안에 어떤 영향이 있습니까?
- **접힘 방식**: 원본 불량 기록은 불량 13종 × (`_1`, `_2`) 열이다. 5종(Short_Shot·Blow_Hole·Exfoliation·Stain·Deformation)은 그대로 두고 **나머지 8종은 "기타불량"으로 묶었다**(예: Bubble은 기타불량 행 중 52건). 한 샷에 2종 이상이 찍힌 85행은 **우선순위로 하나만 남겼다**(미충전 > 기공 > 얼룩, 미충전 > 박리 > 변형로 추정).
- **버려진 정보**: 같은 샷의 동시 불량(예: 미충전+얼룩 19건 → 미충전), `_1/_2` 구분(의미는 데이터로 확정 못 했다), 불량의 개수·정도(값 2·3이 50칸).
- **영향**: ① 기타불량은 8종이 섞여 공통 패턴이 약해 **새 입력에서 기타불량을 76건 중 0건 잡았다**. ② 동시 불량이 한쪽으로 접히면서 숨은 불량이 있어 "놓침"이 실제보다 적게 잡힐 수 있다. ③ 운영안은 "불량 여부"를 중심으로 짰다. 종류별 조치(예: 미충전 대 기공)는 별도로 정해야 한다.
- 이 규칙은 "품질 우선인가 비용 우선인가"라는 판단이라, 현장에서 정해 줘야 한다고 말한다.

## B. 우리 팀에서만 나올 수 있는 질문

### B1. 새 입력에서 불량의 90%를 놓치는데 왜 이 모델을 씁니까?
- 맞다. 새 입력 기준 1안은 불량 **1,182건 중 122건(10%)만 잡고 1,060건(90%)을 놓친다**(그림 4). 정확도 79%는 정상이 78%라 "전부 정상"이라 답해도 나오는 값이다.
- 원인은 입력값만으로 불량을 가르는 정보가 약해서다(AUC 0.74~0.75, 시험한 모든 모델이 같음).
- 대응: ① 같은 모델에서 경보 기준만 낮춘다(×0.1이면 불량의 약 90%를 잡지만 정상의 약 12%에 헛경보). ② 실시간·설명이 우선이면 2안.

### B2. 쌍둥이 행을 외우는 것은 데이터 누수 아닙니까?
- 누수가 아니라 **데이터 구조**다. 정답이나 정답에서 만든 값은 쓰지 않았고, 입력이 같은 행끼리 같은 라벨인 구조(라벨 일치 97.8%)를 모델이 외우는 것이다. 시험 샷의 58%도 같은 구조다.
- 그래서 점수를 현장 성능으로 읽지 않는다고 보고서에 썼다. 검증을 "같은 입력이 있는 샷"과 "없는 샷"으로 나눠 따로 보고한다.

### B3. 앞뒤 사건의 입력을 특징으로 쓰는 것은 규칙 위반 아닙니까? 실시간이 되나요?
- 10/22 강사 답변: **이웃 입력은 허용, 이웃 정답은 실격**. 우리는 입력만 쓰고 정답에서 만든 값은 쓰지 않았다. shot_id는 정렬에만 쓰고 특징에는 넣지 않았다.
- **실시간은 안 된다**: 뒤 사건의 값은 아직 모르므로 사후 분석·일괄 선별용이다. 앞 사건만 쓰면 이득이 사라진다(+0.0045 → −0.0002). 실시간이 필요하면 2안(앞뒤 입력 없음).

### B4. 2안은 팀원이 만든 건데 왜 같이 보여줍니까?
- 1안의 약점(새 입력·새 생산 구간)을 보완하는 **현장성을 높인 안**이기 때문이다. 입력 25개·숲 2개라 설명이 쉽고 뒤 사건 입력이 필요 없다.
- 단, 경보 기준을 각자 맞추면 **두 안의 최저 비용은 4% 안**이다(10:1, 새 입력 660 대 684). 비용을 정하는 것은 모델 종류보다 경보 기준이라고 답한다.

### B5. 비용 비율(놓침 10배)의 근거는 무엇입니까?
- **가정이다.** 현장 자료가 없다. 품질비용 이론의 "1-10-100 경험 법칙"(검사·재작업 대비 고객에게 나간 불량의 비용이 약 10배)을 참고했을 뿐 엄밀한 표준은 아니다.
- 그래서 5:1 / 10:1 / 20:1 세 가지 표를 만들었고, **현장 비율을 알려 주시면 계산기에 바로 넣겠다**고 말한다. 금액은 필요 없다는 강사 답변도 있었다.

### B6. MLP가 트리보다 낮게 나온 이유는? (설계 카드·베이스라인 질문)
- 리더보드 구조(쌍둥이 58%)에서는 트리가 같은 입력을 외워 93%를 맞히고 MLP는 외우지 못한다(MLP 0.289 대 트리 0.58). 반대로 **새 입력에서는 MLP(0.277)와 트리(0.279)가 같다**. 점수 차는 모델 품질이 아니라 "외울 수 있는가"에서 나온다.

### B7. 시드를 바꾸면 점수가 얼마나 흔들립니까?
- 시드 흔들림 약 ±0.005. 시드 4개 평균을 쓴다. 시험 데이터 예측이 시드에 따라 평균 3행(0.1%) 넘게 바뀌지 않았다.
- 라이브로 `SEED = 7`로 바꿔 실행하면 검증 점수가 몇 천분 단위로 달라지는 것을 보여 줄 수 있다.

### B8. 어떤 공정 조건이 중요하게 나왔습니까?
- 유형 2 제품에서 High_Velocity(Short_Shot·Blow_Hole), Coolant_Temp(Blow_Hole), 유형 1 제품에서 Spray_Time(Exfoliation)·Melting_Furnace_Temp(Short_Shot).
- **"중요하다는 건 예측에 쓸모 있다는 뜻이지 원인이라는 뜻이 아닙니다."** 환경 열(공장 온도·습도, 냉각수 온도)은 시기 표지일 가능성이 커 인과로 읽지 않는다.

### B9. AI가 틀린 것 중 가장 중요한 것은?
- "정상 확률에 ×0.3~0.4를 곱하면 0.6을 넘는다": 새 입력만 보면 0.25→0.335지만 리더보드풍은 0.623→0.599·0.580로 내려가 점수용으로는 기각, 운영안(놓침 비용 반영)에서만 사용.
- "탐지율을 올리면 점수도 오른다": 탐지율은 63~67%로 올랐지만 점수는 0.6125→0.6033으로 내려갔다(헛경보 증가).
- "내부 점수가 리더보드를 예측한다": 1안은 어림 0.623 대 실제 0.5987, 2안은 반대로 약 0.02 낮아 오차 방향이 모델마다 달랐다.

### B10. 그래서 현장에서 무엇을 하면 되나요? (결론 한 줄)
- "**불량이다 아니다를 자동으로 판정하지 말고, 위험 순위가 높은 샷부터 검사 대상으로 올리십시오.** 얼마나 올릴지는 놓침 1건이 헛경보 몇 건만큼 비싼지에 달려 있고, 그 비율을 알려 주시면 표에 대입해 정하겠습니다. 유형 2 제품은 High_Velocity 범위를 시험 생산으로 확인해 보시길 권합니다."

## C. 현장 수정 (5분) 준비표 — `main.py` 맨 위 설정

노트북/터미널에 `최종프로젝트_학생배포` 폴더를 열어 두고 시작한다. 실행: `python main.py`(약 80초). 끝에 "불량 n건 중 m건 탐지, 정상 n건 중 m건을 불량이라 함"이 출력된다.

| 요청 | 고칠 곳 |
|---|---|
| "이 열을 빼고 다시 돌려 보세요" | `DROP_COLS = ("열이름",)` |
| "시드를 바꾸면 점수가 얼마나 흔들립니까?" | `SEED = 7` |
| "경보 기준을 바꾸면 헛경보가 몇 건이 됩니까?" | `ALERT_NORMAL_SCALE = 0.7`(낮추면 탐지↑·헛경보↑, 높이면 반대) |
| "다른 모델로 바꿔 보세요" | `MODEL_NAME = "rf"` / `"logistic"` / `"hgb"` / `"rf_et"` |
| "앞뒤 이벤트 특징을 끄세요" | `NEIGHBOR_FEATURES = False` |
| "잎·나무 수·가중치 강도를 바꿔 보세요" | `RF_MIN_LEAF`, `RFET_N_TREES`, `CLASS_WEIGHT_POWER` |

- 말할 때: "이 설정을 바꾸고 다시 실행하면, 출력 마지막 줄에 불량 n건 중 m건 탐지, 정상 n건 중 m건 헛경보가 나옵니다."
- 출력되는 검증 점수(약 0.26)는 "처음 보는 입력" 평가라 리더보드보다 낮은 것이 정상이라고 먼저 말한다.
- 현장 비율이 나오면: 웹 보고서 "07 운영 기준" 계산기의 슬라이더를 그 비율에 맞춘다.

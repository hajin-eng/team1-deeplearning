## 4. 꼭 알아야 할 판단·주의점

1. **public 점수로 모델을 고르지 않는다.** 제출 대상의 약 58%가 train에 같은 입력(쌍둥이)이 있어서 public(0.4089)이 검증(0.325)보다 높게 나옴. public은 1,130행뿐이라 흔들림도 큼. 모델 선택은 항상 쌍둥이 그룹 교차검증으로.
2. **정보 유출 방지:** 결측 채우기·스케일링·class_weight 계산은 Pipeline 안에서 조각마다 학습용으로만. 쌍둥이는 같은 조각에(`StratifiedGroupKFold`). 식별 열(shot_id/id/Shot)과 그룹 번호가 피처에 들어가지 않는지 `check_data()`가 검사.
3. **환경 열:** 포함 0.3248 / 제외 0.2863 → 지금은 포함. 다만 데이터 파트 분석상 "시기 표지" 역할로 추정 → **중요도가 높아도 원인으로 해석하지 않기** (보고서 Q3에 두 숫자 같이).
4. **Product_Type:** RF는 Type 1에 Blow_Hole, Type 2에 Deformation·Exfoliation을 한 번도 예측하지 않음(실제로도 없음, 정상).
5. **발견한 약점:** RF가 **Type 1 샷을 Short_Shot으로 한 번도 예측 안 함 (실제 161개)** → Short_Shot F1이 낮은 이유 후보. 개선 아이디어로 볼 만함.
6. **전처리는 데이터 파트 영역.** preprocess.py가 바뀌면 main.py 쪽에서 받는 형식을 맞추는 방식으로 연동해 왔음.
7. 제품별 모델·앙상블은 쓰지 않기로 함 (팀 문서 3-1-6).

## 6. MLP 시작 가이드

1. **설치:** torch, matplotlib (가상환경 `.venv` 권장). 규칙상 pandas/numpy/sklearn/matplotlib/torch만 사용 가능.
2. 설치 후 `main.py`의 `set_seed()` 안에 있는 `import torch`를 파일 맨 위로 옮기고 try/except 제거.
3. **sklearn처럼 감싸기:** torch 모델엔 `fit`/`predict`가 없으므로 `fit(X, y)`·`predict(X)`를 가진 클래스로 감싸서 `build_model()`에 `elif MODEL_NAME == "mlp":`로 끼움 → 교차검증·평가·제출 코드는 그대로 재사용.
4. **라벨:** 글자 라벨 → 숫자로 바꿔 학습, 예측 후 원래 글자로 되돌리기.
5. **스케일링:** Pipeline 안에서 (조각마다 학습 구간에만 맞춤). MLP는 스케일링 필수.
6. **불균형:** `nn.CrossEntropyLoss(weight=텐서)`에 `make_class_weight(y)` 결과를 넣기 (강도 0.5부터).
7. 시드 고정 확인 (같은 결과가 매번 나와야 함), CPU 10분 이내.
8. 실험 후 RF와 같은 방식으로 **Product_Type별 예측 표** 확인 (4절 4·5번 비교).

- 설계 카드: `02_개념_질문정리.md` 14번(MLP 설계 카드), 18번(softmax), 33번(class_weight → 손실 가중치)

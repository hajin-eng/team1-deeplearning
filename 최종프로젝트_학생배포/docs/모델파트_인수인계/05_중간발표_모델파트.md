## 슬라이드 1. 모델 파트가 한 일 (한눈에)

**핵심 메시지:** 점수를 믿을 수 있게 검증부터 세우고, 그 위에서 모델을 한 단계씩 개선했다.

| 단계 | 한 일 | macro F1 (쌍둥이 그룹 5조각 교차검증) |
|---|---|---|
| 0 | 파이프라인 완성 (`python main.py` 한 줄 → 제출 CSV) | - |
| 1 | 검증 설계: 쌍둥이 그룹 분할 + 5조각 교차검증 | 로지스틱 balanced **0.2255** |
| 2 | 불균형 처리: class_weight 강도 조절 | 로지스틱 강도 0.5 **0.2896** |
| 3 | 모델 변경: 랜덤포레스트 | RF **0.3175** |
| 4 | 데이터 파트 전처리 반영 | RF **0.3248** |
| 5 | 모델 3종 비교 (시드 4개) → 중간 제출 RF | RF 0.326 / HGB 0.305 / 로지스틱 0.287 |
| 6 | **중간 제출** | **public 0.4089** (기준선 0.2517 통과) |

**말할 것:** 모델 파트는 "점수를 어떻게 믿을 수 있게 잴 것인가"를 먼저 정하고, 그 기준으로 가중치, 모델, 전처리를 하나씩 바꿔 가며 확인했습니다. 한 번에 하나만 바꿔서 무엇이 효과가 있었는지 구분할 수 있게 했습니다.

## 슬라이드 2. 검증 설계: 점수부터 믿을 수 있게

**핵심 메시지:** 같은 샷이 두 번 기록된 "쌍둥이"가 있어서, 무작위로 나누면 점수가 부풀려진다. 쌍둥이는 같은 조각에 넣는다.

- 데이터 파트가 발견: **입력이 같은 쌍둥이 행이 42%** (train 쌍둥이 그룹 3,663개)
- 쌍둥이 한쪽이 학습용, 다른 쪽이 검증용에 들어가면 → 모델이 **외워서 맞힘**

| 분할 방식 (같은 모델, 같은 데이터) | 로지스틱 | RF | HGB |
|---|---|---|---|
| 랜덤 분할 (쌍둥이가 갈라짐) | 0.300 | 0.373 | **0.405** |
| **쌍둥이 그룹 분할 (우리 기준)** | 0.295 | 0.325 | 0.302 |
| 차이 (부풀려진 정도) | +0.005 | +0.048 | **+0.103** |

- 외우는 힘이 센 모델일수록 랜덤 분할에서 더 부풀려짐 → 랜덤 분할로 고르면 **외우는 모델을 고르게 됨**
- 검증 방법: `StratifiedGroupKFold` 5조각
  - Group: 쌍둥이는 같은 조각에
  - Stratified: 불량 종류 비율은 조각마다 같게 (기타불량이 한 조각에 몰리지 않게)
  - 5조각이 한 번씩 검증용 → train 전체 예측을 모아 **한 번에 채점**
- 한 번만 나누면 운이 섞임: 예전 0.239는 5조각 중 운 좋은 조각의 점수였고, 실제는 0.226

**말할 것:** 검증용에 소수 클래스가 15~20개뿐이라 한 번 나누면 운이 크게 섞입니다. 그래서 5조각으로 돌려 모든 train 샷을 한 번씩 검증하고, 점수가 ±0.01~0.02 정도 흔들린다는 것도 같이 봅니다. 이보다 작은 차이는 "같다"고 판단했습니다.

## 슬라이드 3. 불균형 처리: class_weight는 "켜기/끄기"가 아니라 "강도"

**핵심 메시지:** balanced 가중치는 너무 세서 정상의 77%를 불량이라고 불렀다. 강도를 0.5(제곱근)로 낮추니 점수가 크게 올랐다.

- 정상 77% → 그냥 학습하면 전부 "정상" (macro F1 0.13)
- balanced = 샷 수가 적은 클래스일수록 크게 벌점: 기타불량 1개 = 정상 1개의 **54배**
- 우리 방법: `가중치 = balanced ** 강도` → 강도 0.5면 차이가 **7.3배**로 줄어듦

| 강도 (로지스틱) | macro F1 | 정상 recall |
|---|---|---|
| 0 (끔) | 0.126 | 0.996 (거의 전부 "정상") |
| 0.25 | 0.205 | 0.955 |
| **0.5** | **0.290** | 0.791 |
| 0.75 | 0.276 | 0.487 |
| 1 (balanced) | 0.226 | 0.235 (정상의 77%를 불량이라고 부름) |

- 너무 약하면 전부 정상, 너무 세면 전부 불량 → **중간이 가장 좋은 산 모양**
- 0.5와 0.6은 점수가 같음(0.2896 vs 0.2895) → **헛경보가 적은 0.5** 선택 (운영 관점)
- 가중치는 교차검증 조각마다 **학습용 정답만으로** 계산 (검증 정보 유출 방지)

**말할 것:** 숫자 하나(강도)로 0.226에서 0.290까지 올랐습니다. 0.5와 0.6은 점수로는 동점이었는데, 0.6은 불량 1개를 더 맞히려고 정상 6개를 헛경보로 냅니다. 현장 재검사 부담을 생각해서 0.5를 골랐고, "불량을 놓치는 게 더 비싸다"는 방향이면 0.6도 가능하다는 점은 운영안에서 다시 이야기하겠습니다.

## 슬라이드 4. 모델 변경: 로지스틱 → 랜덤포레스트

**핵심 메시지:** 로지스틱은 직선이라 학습용 데이터도 못 맞혔다(과소적합). 질문으로 구간을 나누는 RF로 바꾸고, 외우지 않도록 "잎 최소 샷 수"를 조절했다.

- 로지스틱 학습용 F1 0.242 → 본 문제도 못 맞힘 = 직선의 한계
- RF = 스무고개 나무 300그루의 다수결. "형체결력 ≤ 367 **이고** 습도 ≤ 54" 같은 조건 조합 가능
- 잎 최소 1(기본)이면 샷 하나하나를 외움 (학습용 0.97 vs 검증 0.31) → 잎 최소와 강도를 함께 탐색

| 잎 최소 \ 강도 (전처리 반영 후) | 0.25 | 0.5 | 0.75 | 1 |
|---|---|---|---|---|
| 1 | 0.283 | 0.293 | 0.312 | 0.323 |
| 5 | 0.283 | 0.328 | 0.324 | 0.303 |
| **10** | 0.289 | **0.325 (선택)** | 0.325 | 0.277 |
| 20 | 0.272 | 0.316 | 0.314 | 0.268 |
| 40 | 0.233 | 0.294 | 0.301 | 0.251 |

- 좋은 영역: 강도 0.5~0.75 × 잎 5~20 (넓은 언덕)
- **1등 칸이 아니라 언덕 한가운데**를 고름: 20개 중 1등은 운으로 부풀려졌을 수 있고, 주변도 좋은 칸이 새 데이터에서 덜 흔들림

**말할 것:** 하이퍼파라미터를 고를 때 가장 높은 칸 하나를 고르지 않았습니다. 1~3등의 차이가 0.003으로 흔들림(±0.015)보다 훨씬 작았기 때문에, 주변 칸까지 좋은 곳을 골라 안정성을 우선했습니다.

## 슬라이드 5. 데이터 파트 전처리 반영 + 모델 3종 비교

**핵심 메시지:** 데이터 파트 전처리(`preprocess.load_data()`)를 그대로 연결하고, 같은 조건에서 모델 3종을 시드 4개로 비교했다.

- 전처리는 데이터 파트 결정 그대로 사용 (preprocess.py는 수정하지 않고 main.py 쪽에서 형식을 맞춤)
  - 피처 25개 (공정 값 21 + 이상치 표시 열 4), 결측은 앞뒤 실측값 30개씩의 중앙값, 쌍둥이 그룹 3,663개
  - RF 0.3175 → **0.3248**, 흔들림 ±0.018 → ±0.0145

| 모델 | 시드 42 | 0 | 1 | 2 | **평균** | 정상 recall |
|---|---|---|---|---|---|---|
| 로지스틱 (강도 0.5) | 0.295 | 0.285 | 0.284 | 0.286 | 0.287 | 0.788 |
| **RF (잎 10, 강도 0.5)** | 0.325 | 0.319 | 0.335 | 0.323 | **0.326** | 0.816 |
| HGB 설정 B (balanced, 데이터 파트 추천) | 0.302 | 0.310 | 0.307 | 0.302 | 0.305 | 0.577 |

- HGB B는 데이터 파트가 잰 값(시드 0·1 평균 0.308)과 같게 재현됨 → 같은 조건에서 비교한 것 확인
- RF가 시드 4개 모두에서 높고 헛경보도 적음 → **중간 제출은 RF로 결정 (팀 합의)**
- 다만 차이(약 0.02)는 노이즈 기준(±0.03)보다 작아서 최종 모델은 MLP까지 포함해 다시 비교

**말할 것:** 데이터 파트가 HGB를 추천해 줬고, 그 설정을 같은 조건에서 그대로 재현한 뒤 RF와 비교했습니다. RF가 조금 높았던 것은 가중치 강도와 잎 크기를 함께 조절한 효과로 보입니다. HGB에는 약한 가중치가 도움이 되지 않았는데, 이것도 데이터 파트 실험 결과와 같은 방향이었습니다.

## 슬라이드 6. 중간 제출 결과와 해석

**핵심 메시지:** public 0.4089로 기준선을 통과했다. 그러나 검증 점수(0.325)보다 높은 이유는 쌍둥이 때문일 가능성이 커서, 모델 선택은 계속 검증 점수로 한다.

| 기준 | macro F1 |
|---|---|
| 강사 공개 기준선 | 0.2517 |
| 우리 검증 (쌍둥이 그룹 분할) | 0.325 |
| 우리 검증 (랜덤 분할, 참고) | 0.373 |
| **public 리더보드 (1회차, 남은 9회)** | **0.4089** |

- 제출 대상의 약 58%는 **같은 입력이 train에 있음**(쌍둥이) → 리더보드는 쌍둥이 그룹 분할보다 랜덤 분할 쪽에 가까움
- public은 1,130행뿐이라 소수 클래스가 적어 점수가 크게 흔들릴 수 있음
- 강사 코멘트: public 점수만 보고 모델을 고르면 private에서 순위가 뒤집힐 수 있음 → **우리 원칙과 같음**
  - public 점수는 참고만, 모델 선택은 train 안의 쌍둥이 그룹 교차검증으로

**말할 것:** 리더보드 점수가 검증보다 0.08 높게 나왔지만, 이것을 모델 실력으로 보지 않습니다. 쌍둥이가 test에도 있어서 외우는 모델일수록 리더보드에서 유리해 보일 수 있기 때문입니다. 실제로 HGB는 랜덤 분할에서 0.405로 RF보다 높았습니다. 그래서 최종 모델도 검증 점수로 고를 계획입니다.

## 슬라이드 7. 지금 모델의 모습과 한계

**핵심 메시지:** 정상은 잘 구분하지만 소수 불량(기타불량, Short_Shot, Exfoliation)은 아직 약하다.

| 클래스 (RF, 교차검증) | precision | recall | F1 |
|---|---|---|---|
| 정상 | 0.850 | 0.819 | 0.834 |
| Blow_Hole | 0.310 | 0.412 | 0.354 |
| Stain | 0.233 | 0.650 | 0.343 |
| Deformation | 0.196 | 0.623 | 0.298 |
| Exfoliation | 0.242 | 0.157 | 0.190 |
| Short_Shot | 0.274 | 0.124 | 0.170 |
| 기타불량 | 0.091 | 0.079 | 0.085 |

- 현장 지표: **불량 탐지율 50%** (불량 샷을 불량 중 하나로 알림), **정상 헛경보율 18%**
- 제품별 불량 구분은 잘 함: Type 1 샷에 Blow_Hole, Type 2 샷에 Deformation·Exfoliation을 한 번도 예측하지 않음 (실제로도 없음)
- 약점 발견: Type 1 샷을 Short_Shot으로 한 번도 예측하지 않음 (실제 161개) → Short_Shot F1이 낮은 이유 후보
- 환경 열(공장 온도·습도 등)을 빼면 0.325 → 0.286. 데이터 파트 분석상 **시기를 알려 주는 표지** 역할로 추정 → 중요도가 높아도 원인으로 해석하지 않음

**말할 것:** 정상은 F1 0.83으로 잘 가려내지만, 기타불량과 Short_Shot은 아직 거의 못 잡습니다. 환경 열은 점수에는 도움이 되지만 불량의 원인이라기보다 "그 시기"를 알려 주는 역할로 보여서, 원인 분석에서는 조심해서 다루겠습니다.

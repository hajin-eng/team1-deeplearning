# 전처리 결정 정리 (2026-10-16 전면 개정)

`preprocess.py`와 `analysis/` 폴더를 기준으로 다시 정리한 문서입니다. 전처리 담당이 정한 결정과 그 근거를 적었고, 숫자는 모두 직접 계산한 값입니다. **(추정)** 표시는 데이터로 확정하지 못한 해석입니다. 모델 파트에 넘길 일은 `실험결과_및_할일.md`에 있습니다.

## 용어

- **macro F1**: 클래스 7개(정상, Short_Shot, Blow_Hole, Exfoliation, Deformation, Stain, 기타불량)의 F1을 단순 평균한 점수입니다. 공개 기준선은 전부 "정상" 0.1248, 로지스틱 0.1313, 로지스틱(class_weight) 0.2517입니다.
- **쌍둥이**: 바로 앞 행과 입력값 21개가 모두 같은 행입니다 (3,174행, 42%).
- **쌍둥이 그룹 분할**: 입력이 같은 행을 한 묶음으로 보고, 묶음이 학습과 검증에 갈라지지 않게 나눈 5-fold 검증입니다. **이 문서에서 점수를 비교하는 기준**입니다.
- **랜덤 분할**: 쌍둥이가 학습과 검증에 갈라져서 점수가 부풀려집니다. 시간순은 앞 80%로 학습해 뒤 20%를 맞히는 방식이고, 한 번뿐이라 노이즈가 큽니다.
- **±**: 표준편차입니다. 점수 차이가 이보다 작으면 노이즈로 봅니다 (대개 0.02~0.03).
- **환경 열 6개**: Factory_Temp, Factory_Humidity, factory_missing, Air_Pressure, Coolant_Temp, Coolant_Pressure (`ENV_COLS`).

## 2. 데이터에서 확인한 사실

### 2-1. 파일과 열 (analysis/01)

- 입력 7,535행 = train 5,274 + test 2,261 (public + private). 분할표·정답 파일과 행이 맞습니다.
- 값이 하나뿐인 상수 열 8개는 공장 온도·습도의 Min/Max 등입니다. 모델이 배울 것이 없어 뺍니다.
- 공장 온도·습도의 Min/Max(18~22)는 실측(온도 27~37℃, 습도 45~72%)과 맞지 않습니다. 습도 범위가 온도 범위와 같아 복사 오류로 보입니다 **(추정)**. 틀린 것은 측정값이 아니라 기준(Min/Max)으로 판단해 측정값은 그대로 둡니다.
- 결측은 공장 온도·습도 6개 열이 같은 90행에서 비어 있습니다 (train 63 / test 27, 전부 Type 2, 두 덩어리: shot 6914~6977, 7042~7067).
- 정상이 train의 77.6%(4,092행)입니다.

### 2-2. 제품과 시기

- shot 1~4207은 Type 1, 4208~7535는 Type 2입니다. 주조압 1052 vs 596, 형체력 257 vs 375 등 조건이 크게 다릅니다.
- Type 1 안에서도 shot 3480~3512 사이에 설정이 바뀝니다 (Casting_Pressure 1052 → 1155, Cylinder_Pressure 217 → 239, Cycle_Time 20.8 → 22.6). 이후 구간(3414~4207)은 불량이 거의 없습니다 (580행 중 7행). 시기와 겹친 교란이라 원인 해석에 주의해야 합니다.
- Shot 번호는 shot_id 1100, 3414, 4208(제품 전환과 같음), 4808, 6258, 6266에서 리셋됩니다. 식별 열이라 특징으로 쓰지 않습니다.
- 불량이 제품·시기에 몰려 있습니다. Deformation 106건·Exfoliation 198건은 전부 Type 1, Blow_Hole 233건은 전부 Type 2입니다. Deformation은 shot 1~1099에만, Blow_Hole은 4434 이후에만 있고, Stain의 98%는 4808~6257에 있습니다. 1,000샷 단위 불량률이 4%~46%입니다. 시간순 검증에서 검증 구간에 없는 클래스가 생기는 이유이고, 원인 분석에서는 공정 조건 차이와 시기·제품 차이를 구분해야 합니다.
- 센서 고정: Air_Pressure(최장 196행), Coolant_Temp(최장 270행)가 같은 값으로 길게 이어집니다. 값이 바뀌는 지점이 Shot 리셋과 무관해서 오류로 볼 근거가 없어 그대로 둡니다.
- Cylinder_Pressure와 Casting_Pressure는 제품 안에서도 거의 같은 값입니다 (상관 Type 1 1.00, Type 2 0.89). Clamping_Force, Spray_1/2가 제품과 상관이 높은 것은 제품을 따라 움직이기 때문이고 제품 안에서는 낮습니다.
- Spray_Time은 Spray_1 + Spray_2가 아닙니다 (차이 3.3~8.9). 정의를 몰라서 합계 파생 변수는 만들지 않습니다.

## 3. 처리 방법별 근거

### 3-1. 결측 채우기 (analysis/04)

RF, 쌍둥이 그룹 분할, 15회 평균입니다.

| 채우기 방식 | macro F1 |
| --- | --- |
| 전체 중앙값 | 0.235 |
| 앞뒤 중앙값 window 10 | 0.234 |
| **앞뒤 중앙값 window 30 (선택)** | **0.231** |
| 앞뒤 중앙값 window 60 | 0.233 |
| 선형 보간 | 0.232 |

- 표준편차가 약 0.03이라 0.004 차이는 구분되지 않습니다.
- 같은 모델로 test 결측 27행을 예측하면 채우는 방식에 따라 답이 달라지는 행이 0~3개뿐입니다.
- 결측이 있는 Factory_Humidity는 RF 변수 중요도 1위, Factory_Temp는 4위, `factory_missing`은 22위(0.001)입니다.
- window 30을 고른 이유: 점수로 못 가르므로 근거로 정했습니다. 결측 구간 바로 뒤의 튀는 값 3개 샷(6978, 7068, 7070)이 섞여도 중앙값이 흔들리지 않고, 습도의 국소 변동(표준편차 1.7) 범위에 맞습니다.
- 채워진 값: shot 6914~6977은 습도 65.8·온도 32.35, shot 7042~7067은 습도 70.0·온도 31.8 (이전 전체 중앙값 방식은 습도 63.0·온도 32.1).

### 3-2. 값이 안 맞는 것은 어떻게 다루나

**앞뒤 실측값 중앙값은 결측(NaN)에만 적용합니다.** 범위를 벗어나거나 이상해 보이는 "값"을 이 방법으로 바꾸지 않습니다.

| 값이 안 맞는 경우 | 처리 | 이유 |
| --- | --- | --- |
| 공장 온도·습도 Min/Max와 실측이 안 맞음 | Min/Max 열 제거, 측정값은 그대로 | 위 2-1 참고 |
| 결측 90행 | 앞뒤 실측값 30개씩의 중앙값으로 채움 + `factory_missing` 표시 | 값이 아예 없어서 채울 수밖에 없음 |
| 결측 구간 바로 뒤의 튀는 값 3개 샷 | 그대로 | 영향 없음. 이상 기준을 임의로 만들게 됨 |
| 속도·승압시간 0 (4샷, 3348·3349·3420·3421) | 그대로 + `is_restart` | 설비 정지·재가동으로 보임. Cylinder_Pressure 107~108, Cycle_Time 106~218초 |
| 비스킷 두께 0 (4샷) | 그대로 + `bad_biscuit` | 물리적으로 불가능한 값이지만 사실 정보를 보존 |
| Cycle_Time 60초 초과 (11샷) | 그대로 + `long_cycle` | 위와 같은 이유 |

이상한 값을 가진 행은 합집합 15개(train 11, test 4)입니다. 앞뒤 중앙값으로 바꾸는 것은 하지 않고, **현재처럼 유지**합니다. 해당 행이 15개뿐이고 바꾸려면 이상 기준이 먼저 필요합니다. train에서 삭제하는 것은 `load_data(drop_flagged_train=True)`로 할 수 있고, 점수 비교 결과는 3-5에 있습니다 (차이 없음).

### 3-3. 중복 행 (analysis/02, 05)

**구조 (확인된 사실)**

- Shot 번호가 같은 연속 행은 항상 정확히 2행이고(2,918쌍), 입력이 전부 같습니다. Shot 번호가 같은데 입력이 다른 경우는 0건입니다.
- 한 행뿐인 Shot 번호는 1,699개입니다.
- 4행 묶음 146개는 `Shot a`가 2행, `Shot a+1`이 2행이고 입력이 전부 같습니다. 2행 묶음 중 110개는 서로 다른 Shot 번호인데 입력이 같습니다. 이 256개 묶음(110쌍 220행 + 4행 묶음 584행 = 804행, 전체의 10.7%)은 Shot 번호가 달라서 생긴 것으로, 왜 번호가 달라졌는지는 설명되지 않았습니다.
- 우연이 아닙니다. 입력이 다른 이웃 행은 21개 열 중 중앙값 9개가 다릅니다.
- train에서 두 행이 모두 있는 쌍 1,393개 중 1,361개(97.7%)가 원본 불량 기록 26열까지 똑같고, 라벨도 97.8%가 같습니다. 독립된 두 부품이라면 라벨 일치가 약 61%여야 합니다. (4행 묶음까지 포함한 그룹 전체로는 라벨 일치 1,429개 / 불일치 57개)
- 테스트 2,261행 중 1,305행(58%)은 같은 입력의 행이 train에 있습니다. 랜덤 분할과 리더보드 점수가 부풀려지는 이유입니다.
- 해석은 "한 번의 사출이 2행으로 기록됨(부품 2개)"과 "같은 기록이 두 행으로 복제됨" 두 가지가 남고, 데이터로는 구분되지 않습니다.

**실험 결과** (쌍둥이 그룹 분할 5-fold × 시드 3, 전체 모드)

| 모델 | 그대로 | 가중치(1 / 그룹 크기) | 그룹당 1행 |
| --- | --- | --- | --- |
| RF | 0.231 | 0.235 (나아진 횟수 9/15) | 0.224 (5/15) |
| HGB | 0.283 | 0.284 (9/15) | 0.290 (8/15) |

- 모든 차이가 ±0.008 이내이고 표준편차(0.03)보다 훨씬 작아서 어느 쪽도 일관되게 낫지 않습니다. (빠른 모드에서는 HGB의 그룹당 1행이 +0.013(4/5)까지 나왔지만 표준편차 안쪽입니다.)
- 시간순 80/20에서 RF의 그룹당 1행이 0.292로 높게 나왔지만 HGB에서는 0.228이라 노이즈입니다.

**선택: 행을 그대로 유지**합니다. 낫다는 근거가 없으면 가장 단순한 쪽이 맞고, test에도 같은 구조가 있어서 학습도 같은 구조로 두는 게 일관됩니다. 가중치는 해가 없으니 모델 파트가 원하면 선택할 수 있습니다 (`sample_weight`, 05번 코드 참고).

### 3-4. 환경 열이 시계 역할을 하는가 (analysis/06, 09)

수기 입력 가설은 데이터로 확정할 수 없지만 모순되지 않는 흔적이 있습니다 (03번 F~H).

| 점검 | 결과 |
| --- | --- |
| 소수 첫째 자리 쏠림 | Factory_Temp만 .0이 22%(기대 약 10%). 습도·공기압·냉각수는 쏠림 없음 |
| 값이 바뀌는 시점 | 공장·공기압·냉각수 열이 같은 시점에 같이 바뀜 (우연 기대치의 약 2.3배) |
| 튀는 값 | 결측 구간 바로 뒤 3개 샷에서만 나오고 6978·7070은 온도·습도가 함께, 7068은 습도만 어긋남 → 타이핑 실수보다 복구 직후 값처럼 보임 **(추정)** |

환경 열을 빼면 그룹 분할 점수는 떨어지고 시간순은 거의 변하지 않습니다 (06번, RF, 그룹 분할 15회 / 시간순 80/20 한 번).

| 사용 열 | 그룹 분할 F1 | 시간순 F1 |
| --- | --- | --- |
| 전부 25개 | 0.231 (±0.027) | 0.219 |
| 공장 온도·습도 제외 | 0.206 (±0.025) | 0.220 |
| 환경 열 6개 제외 | 0.159 (±0.019) | 0.216 |

트리 모델 3종 모두 같은 방향입니다 (09번, 전체 모드 기준. 시간순은 검증 구간에 있는 클래스만 평균).

| 모델 | 그룹 분할 (포함 → 제외) | 제외가 나은 횟수 | 시간순 (포함 → 제외) |
| --- | --- | --- | --- |
| RandomForest | 0.231 → 0.159 | 0/15 | 0.292 → 0.288 |
| ExtraTrees | 0.249 → 0.160 | 0/15 | 0.300 → 0.289 |
| HGB | 0.283 → 0.244 | 1/15 | 0.296 → 0.323 |

- 습도 같은 센서가 시기에 따라 천천히 변해서, 모델이 "지금이 언제인지"를 알려 주는 표지로 쓰는 것으로 보입니다 **(추정)**.
- 리더보드(랜덤 분할)에서는 도움이 되지만 실제 배포 성능과는 다를 수 있습니다. 그래서 환경 열은 유지하되 "포함 / 제외" 두 버전을 모두 측정합니다.
- 시간순은 한 번뿐이라 HGB의 0.323은 노이즈일 수 있습니다.
- 보고서 6번(무작위 vs 시간순)과 8번(중요도 ≠ 원인)의 근거로 쓸 수 있습니다.

### 3-5. 이상치 행 삭제 / Cylinder_Pressure 제거 / 클래스 불균형 (analysis/10)

모두 쌍둥이 그룹 분할 5-fold × 시드 3(15회), 전체 모드입니다. 이상치 삭제와 Cylinder_Pressure 제거는 **train에서만** 바꾸고 검증 행은 전부 씁니다. 불균형 처리는 HGB로, 오버샘플링은 학습 폴드 안에서만 했습니다.

| 비교 | RF | HGB |
| --- | --- | --- |
| 기본 (25개 열, 이상치 행 유지) | 0.231 (±0.027) | 0.283 (±0.031) |
| 이상치 11행 삭제 | 0.232, +0.001 (9/15) | 0.289, +0.006 (10/15) |
| Cylinder_Pressure 제거 | 0.228, -0.003 (7/15) | 0.291, +0.008 (10/15) |

- **이상치 삭제가 전처리를 깨뜨리는가**: 구조는 깨지지 않습니다. `load_data(drop_flagged_train=True)`는 train을 5,274행에서 5,263행으로 줄이고 test는 2,261행 그대로 둡니다. 삭제된 11행은 정상 10 / Exfoliation 1입니다. 다만 삭제하면 train의 표시 열 3개가 전부 0이 되어, test에 남은 4행(`bad_biscuit` 2, `long_cycle` 2)은 모델이 본 적 없는 값을 예측해야 합니다. 점수 차이도 표준편차 안쪽이라 **삭제할 이유가 없어서 유지**합니다.
- **Cylinder_Pressure**: 모델에 따라 방향이 갈리고 표준편차 안쪽이라 **유지**합니다. 모델 파트가 최종 모델에서 다시 비교해도 됩니다 (`drop_cols=("Cylinder_Pressure",)`).

| 클래스 불균형 처리 (HGB) | macro F1 | balanced 대비 (나아진 횟수) | 불량 탐지율 | 정상 헛경보율 |
| --- | --- | --- | --- | --- |
| 가중치 없음 | 0.258 | -0.025 (1/15) | 16.9% | 5.8% |
| balanced (기준) | 0.283 | - | 30.4% | 13.2% |
| 제곱근 가중치 | 0.268 | -0.015 (4/15) | 22.6% | 8.2% |

| 확률 보정 | 0.302 | **+0.019 (12/15)** | 49.8% | 24.9% |

- 가중치 없음·제곱근 가중치·오버샘플링은 balanced보다 낫지 않습니다 (오버샘플링은 차이가 +0.001이라 같은 수준).
- **확률 보정**(가중치 없이 학습한 뒤 예측 확률을 학습 데이터의 클래스 비율로 나눔)만 balanced보다 높고 12/15 폴드에서 앞섰습니다. 차이 0.019는 표준편차(0.03)보다 작아서 확정은 아니지만, 일관성은 가장 좋습니다.
- 점수가 오르는 대가로 **정상 헛경보율이 13% → 25%로 늘어납니다.** 운영 기준(불량을 얼마나 잡고 정상을 얼마나 잘못 경보할지)에 따라 선택이 달라집니다.
- 이 비교는 HGB 기본 설정에서 한 번 해 본 것입니다. 최종 모델에서 다시 비교하는 일은 모델 파트의 몫입니다.

## 4. 원본 불량 기록의 `_1/_2`: 의미는 못 찾았고, 정답 라벨에서는 구분이 사라진다 (analysis/03)

**한 줄 요약**: `_1/_2`가 무엇을 뜻하는지는 데이터로 확정하지 못했습니다. 가설 3개(위치 / 단계 / 부품)를 세우고 검증했지만 어느 하나를 확정할 증거는 없었습니다. 정답 라벨은 `_1`과 `_2`를 합쳐서 만들어졌고 어느 쪽이었는지를 담지 않으므로, **의미를 몰라도 모델 제작과 제출은 진행할 수 있고, 전처리에서 `_1/_2`를 합치거나 고칠 필요도 없습니다.**

### 4-1. 파일 구조와 용어

- `참고_원본불량기록_train.csv`는 열이 27개입니다. `shot_id` 하나와, 불량 유형 13종이 각각 `_1`, `_2`로 두 번씩 나옵니다 (예: `Short_Shot_1`, `Short_Shot_2`).
- train 5,274샷에 대해서만 있고 test에는 없습니다.
- 값은 대부분 0/1인데 **2가 49칸, 3이 1칸** 있습니다 (PDF는 "발견되면 1"이라고 했음). 불량의 개수나 정도일 수 있지만 확인할 방법이 없습니다 **(추정)**.

| 용어 | 뜻 (불량 유형 하나, 예: Short_Shot 기준) |
| --- | --- |
| `_1`열에만 | `Short_Shot_1`은 1 이상이고 `Short_Shot_2`는 0인 행 |
| `_2`열에만 | `Short_Shot_2`는 1 이상이고 `Short_Shot_1`은 0인 행 |
| 두 열 모두 | 둘 다 1 이상인 행 |
| 어느 열에도 없음 | 둘 다 0인 행 (다른 유형의 불량은 있을 수 있음) |

### 4-2. 데이터로 확인된 사실

| 확인한 것 | 결과 |
| --- | --- |
| `_1`과 `_2`는 같은 값의 사본인가 | **아님.** 불량이 한 번이라도 찍힌 1,182행 중 1,159행(98%)에서 `_1`과 `_2`가 다름 |
| 같은 불량을 두 번 적은 기록(재검사)인가 | 아님. 같은 유형이 두 열에 동시에 찍히는 경우는 0~7% (Short_Shot 7행, Blow_Hole 11행, Exfoliation 7행, Deformation 3행) |
| 유형별 차이 | Stain은 `_1`에만 있음 (133 vs 0). 5종 합계는 `_1` 845건 / `_2` 367건으로 2.30배 |
| 제품·시기에 따른 변화 | `_1` 비율은 Type 1 → 2에서 0.122 → 0.226 (1.85배), `_2`는 0.068 → 0.078 (1.15배) |
| 한 행에 서로 다른 불량이 2개 이상 | **85행**. `_1`과 `_2`에 나뉜 경우 59, 모두 `_1`인 경우 26, 모두 `_2`인 경우 0 |
| 쌍둥이 쌍의 첫째·둘째 행과 관계 | 없음 (`_1` 불량률 0.171 vs 0.164) |

### 4-3. 가설과 검증

가설을 **두 층**으로 나눠서 봅니다. "같은 Shot이 왜 2행인가"(행 층)와 "`_1/_2`가 무엇인가"(열 층)는 별개의 질문입니다.

**행 층**

| 후보 | 데이터가 말하는 것 |
| --- | --- |
| ① 두 부품을 각각 한 행으로 기록 | **불리.** 쌍 1,393개 중 97.7%의 불량 기록이 26열까지 같고 라벨도 97.8%가 같음. 독립된 두 부품이라면 라벨 일치가 약 61%여야 함 |
| ② 같은 샷 단위 기록이 두 행으로 복제 | **유리.** 다만 32쌍(2.3%)은 기록이 달라서 완전한 복제는 아님 |

**열 층**

| 가설 | 내용 |
| --- | --- |
| A. 검사 위치(면) 2곳 | 제품의 서로 다른 면(또는 부위)을 각각 검사 |
| B. 검사 단계 2회 | 1차 검사와 2차 검사 |
| C. 부품(캐비티) 2개 | 한 번의 사출에서 나온 두 부품의 기록. 기획서의 가설. 행 층 **②를 전제해야 일관**됨 |

| 관찰 (03번의 I~L) | 값 | A 위치 | B 단계 | C 부품 |
| --- | --- | --- | --- | --- |
| 건수 대칭 (I-1) | `_1` 845 / `_2` 367, Stain 133 vs 0 | 가능 | 가능 | **불리** |
| 겹침 (I-2): 같은 1000샷 구간에서 두 열이 무관할 때의 기대와 비교 | 관찰 28 / 기대 27.4 (1.0배) | 중립 | **불리** (1차에서 걸린 불량이 빠진다면 기대보다 적어야 함) | 중립 |

**종합**

- 세 가설 중 하나를 확정하는 증거는 없습니다.
- 상대적으로 C는 건수 비대칭과 제품 반응에서 불리하고, B는 겹침에서 불리하며, A는 뚜렷한 반증이 없습니다. 다만 A가 맞다는 증거도 아닙니다.
- 겹침은 시기를 통제하면 독립일 때와 같습니다(1.0배). 한 열에 불량이 찍혔다고 해서 같은 유형이 다른 열에도 찍힐 확률이 시기 효과 이상으로 높아지지 않습니다.
- J는 두 열이 같은 현상의 사본이 아니라는 단서입니다. 어느 가설과 맞는지는 알 수 없습니다.
- K에서 `_2`열에 찍힌 불량도 공정 조건으로 설명되는 불량이라는 것은 확인됩니다. Deformation의 큰 차이는 해당 행이 특정 시기에 몰려 모델이 시기로 맞히는 것일 가능성이 있습니다 (미확인).

### 4-4. 정답 라벨에서 구분이 사라지는 이유

1. **라벨은 `_1`과 `_2`를 둘 다 보고 만들어졌습니다.** 우선순위(Short_Shot > Blow_Hole > Exfoliation > Deformation > Stain > 기타)로 접었을 때 정답과의 불일치가 두 열을 모두 쓰면 0건, `_1` 열만 쓰면 323건, `_2` 열만 쓰면 830건입니다. (Stain과 Deformation이 함께 찍힌 행이 없어 이 둘의 순서는 데이터로 구분할 수 없습니다.)
2. **어느 쪽에 찍혔는지는 라벨에 담기지 않습니다.** 한 라벨 안에 `_1`열 불량과 `_2`열 불량이 섞여 있습니다.
3. **Stain은 라벨에서 쓰입니다.** 안 쓰이는 것은 `_1`이었는지 `_2`였는지의 구분입니다. Stain이 찍힌 133행 중 33행은 더 우선순위가 높은 Short_Shot(19)·Blow_Hole(14)이 같이 찍혀서 다른 라벨이 붙었습니다.
4. **합쳐지면서 함께 사라지는 정보**: `_1/_2` 구분, 값 2·3, 함께 찍힌 85행의 두 번째 불량(Short_Shot 라벨 안의 Blow_Hole 21건, Stain 19건, Exfoliation 9건), 우선순위에 밀린 불량.
5. 원본 파일에는 남아 있고, 우리가 학습·예측하는 **정답 라벨에서** 구분할 수 없게 된다는 뜻입니다. 원본은 test에 없고 PDF가 특징·라벨 재생성을 금지해서 모델이 쓸 수도 없습니다.

### 4-5. 의미를 몰라도 되는가

| | 의미를 몰라도 되나 |
| --- | --- |
| 모델 제작과 제출 | **됨.** 모델은 7종 라벨만 맞히고 `_1/_2` 구분은 정답에 없음 |
| 전처리 | **됨.** `_1/_2`를 합치거나 고칠 필요가 없음 (기획서의 방향과 같음) |
| 보고서·구술의 "버려진 정보가 모델과 운영안에 주는 영향" | 의미를 알면 구체적으로 쓸 수 있고, 모르면 한계로 명시해야 함 |

모델 파트가 쓸 수 있는 곳은 모델이 못 잡는 불량이 `_1`열에 찍힌 것인지 `_2`열에 찍힌 것인지 나눠서 오류를 해석할 때입니다 (읽는 용도만. 03번의 K가 그 예).

**의미를 확정하지 못한 채 모델 파트가 진행하는 방법 (추천)**

1. **가설 하나를 전제로 모델을 설계하지 않습니다.** 모델 입력과 라벨은 `_1/_2`와 무관하므로 설계에 영향이 없습니다.
2. **오류 분석 단계에서만 `_1/_2`를 읽습니다.** 못 잡은 불량이 `_1`열에 찍힌 것인지 `_2`열에 찍힌 것인지 나눠 재현율을 비교하면(03번의 K), 두 열의 불량이 모델에게 다르게 보이는지 알 수 있습니다. 이 결과는 가설을 확정하지는 못하지만 한계를 구체적으로 쓰는 재료가 됩니다.
3. **운영안에는 가설별 조건부 문장으로 씁니다.** "`_1/_2`가 위치라면 ~, 단계라면 ~, 부품이라면 ~" 형태로 쓰고, 어느 가설이든 이 구분을 알려 줄 수 없다는 공통 한계를 함께 적습니다.
4. **가장 약한 가설은 부품(C)입니다.** 건수 비대칭과 제품 변화 반응에서 불리했고(4-3), 위치(A)는 뚜렷한 반증이 없습니다. 다만 A가 맞다는 증거도 아니므로 보고서에서 A를 사실처럼 쓰지 않습니다.
5. **보고서 문장은 아래 4-6의 제안문을 그대로 쓸 수 있습니다.**

| `_1/_2` 처리 방침 | 원본 기록은 읽는 용도로만 | **일치** |
| `_1/_2`의 의미 | "캐비티 2열"로 추정, 행 묶음과 "대응" | 캐비티는 가설 C로 남김. **행과 열의 대응은 지지되지 않음** (두 행 모두 `_1`과 `_2`를 갖고 기록이 97.7% 같음) |
| 동시 불량 샷 | 78샷 | 이름 있는 5종 기준 78, 기타 유형까지 13종 기준 85. 정의 차이 |
| 접기 순서 | ... > Stain > Deformation > 기타 | Stain·Deformation이 함께 찍힌 행이 0개라 어느 순서든 같음 |
| Bubble | 53건 | 라벨이 기타불량인 행 중 52건, 원본 전체는 57건 |

> `_1/_2`의 의미는 제공된 데이터만으로 확정하지 못했다. 위치(면), 검사 단계, 부품(캐비티)의 세 가설을 세워 검증했으나(두 열의 건수 비대칭, 시기를 통제한 겹침, 제품 변화 반응, 공정 조건 차이, 모델 재현율), 하나를 확정할 증거는 없었다. 확인된 것은 두 열이 서로 다른 정보이고(불량이 있는 행의 98%에서 값이 다름), 정답 라벨은 둘을 합쳐서 만들어졌다는 점이다(합쳐서 접으면 정답과 불일치 0건). 그래서 라벨에서는 구분이 사라지고, 모델과 운영안에서는 이 정보를 쓸 수 없다. 의미가 확정되지 않았으므로 가설별로 영향을 나누어 서술하고(위치라면 어느 부위, 단계라면 어느 검사에서, 부품이라면 어느 부품이 불량인지 알려 줄 수 없다), 한계로 명시한다.

## 5. 전처리 이후 모델 점수 (참고, analysis/07·08·09)

전처리를 적용하고 모델은 모두 기본 설정으로 돌린 결과입니다. 모델 선택은 모델 파트의 몫이고, 여기서는 전처리 결과가 점수에 어떻게 나타나는지 확인하는 용도입니다.

| 모델 | 랜덤 (1회) | 쌍둥이 그룹 (15회) | 시간순* | 불량 탐지율 | 정상 헛경보율 |
| --- | --- | --- | --- | --- | --- |
| 로지스틱(balanced) | 0.228 | 0.223 ± 0.016 | 0.123 | 95.1% | 77.1% |
| RandomForest | 0.552 | 0.231 ± 0.027 | 0.292 | 10.0% | 2.8% |
| ExtraTrees | 0.548 | 0.249 ± 0.024 | 0.300 | 13.6% | 3.4% |
| HistGradientBoosting | 0.535 | 0.283 ± 0.031 | 0.296 | 29.8% | 13.9% |
| MLP(sklearn) | 0.013 | 0.051 ± 0.075 | 0.000 | 96.7% | 87.3% |

\* 앞 80%로 학습해 뒤 20%를 맞히고, 검증 구간에 실제로 있는 클래스만 평균했습니다. 탐지율은 실제 불량 중 "정상이 아니라고" 예측한 비율(어떤 불량인지는 안 봄), 헛경보율은 실제 정상 중 "불량이라고" 예측한 비율이며 쌍둥이 그룹 분할(시드 0)로 계산했습니다.

- 가중치 없는 로지스틱은 0.130이라 공개 기준선 0.1313과 맞고, class_weight를 주면 0.223입니다 (기준선 0.2517). 우리 파이프라인이 기준선과 같은 방식으로 동작한다는 확인입니다.
- 트리 모델은 랜덤 분할에서 0.53~0.55, 그룹 분할에서 0.23~0.28입니다. 리더보드가 랜덤 분할이라 트리 모델의 리더보드 점수는 부풀려질 가능성이 큽니다 **(추정)**.
- 그룹 분할 1위는 HGB 0.283이지만 표준편차(0.02~0.03) 때문에 나머지 사이는 구분이 어렵습니다.
- 같은 점수여도 로지스틱은 많이 잡고 많이 틀리고, 트리는 거의 안 틀리지만 거의 못 잡습니다.
- 로지스틱에서 환경 열 6개를 빼면 balanced 그룹 점수가 0.223 → 0.175로 떨어집니다 (07번).
- HGB 설정 8가지 비교 (09번): 전체 모드에서 그룹 분할 최고는 0.306이었고 다른 시드로 다시 재면 기준(0.287) 대비 +0.009로 줄었습니다. 빠른 모드(시드 1개)에서는 B(리프 15, lr 0.05, 100회)가 0.310으로 최고였고(A 기준 0.275), 새 시드에서 0.303 vs 0.287(+0.016)이었습니다. 조정으로 얻는 것은 약 +0.01~0.02입니다. 전체 모드의 최고 설정 이름은 이 문서에 기록하지 않았으므로, 후보는 다시 확인해야 합니다.
- MLP(sklearn)는 확률 보정이 실패한 결과라 무효입니다. PyTorch로 설계할 MLP와는 다릅니다.

## 8. 남은 확인 사항

결정이 끝난 것과 아직 확인하지 못한 것을 나눠 적었습니다.

**결정 완료**

- `_1/_2` 의미: 강사에게 묻지 않고, 우리가 세운 가설 3개(위치 / 단계 / 부품, 4번)를 바탕으로 진행합니다. 확정하지 못한 채로 보고서에 한계로 적고, 모델 파트가 다루는 방법은 4-5에 정리했습니다.
- 이상치 행 15개: 삭제하지 않고 유지합니다. 삭제해도 전처리 구조는 깨지지 않지만(train 5,274 → 5,263행, test 그대로) 점수 차이가 없고, 삭제하면 test의 해당 4행이 학습에 없던 값이 됩니다 (3-5).
- Cylinder_Pressure: 비교했고(RF -0.003, HGB +0.008, 표준편차 안쪽) 유지합니다 (3-5).
- 클래스 불균형: 한 번 비교했습니다 (3-5). 가중치 없음·제곱근 가중치·오버샘플링은 balanced보다 낫지 않았고, 확률 보정만 +0.019(12/15)였지만 정상 헛경보율이 13% → 25%로 늘어납니다. 최종 선택은 모델 파트가 운영 기준과 함께 정합니다.
- 쌍둥이 그룹 기준: 입력 동일 기준을 계속 씁니다 (3-6).

**끝까지 확인하지 못한 것 (다시 확인한 결과와 대처)**

| 항목 | 다시 확인한 결과 | 그래도 모를 때 대처 |
| --- | --- | --- |
| 번호가 달라도 입력이 같은 256개 묶음(804행) | 전부 shot_id가 연속이고 Shot 번호가 정확히 1 차이. Shot 리셋 지점 근처는 0건. 같은 입력이 인접 그룹 밖에 있는 경우도 0건 | 원인과 상관없이 입력 동일 기준 그룹이 이 행들을 이미 묶고 있으므로 전처리와 검증은 안전함. 보고서에 "원인 미확인, 입력 동일 기준으로 처리"라고 기록 |
| 한 행뿐인 Shot 번호 1,699개 | 위 256개 묶음과 합쳐 Shot 번호만으로는 행 구조를 설명하지 못함 | Shot 번호는 식별 열이라 특징으로 쓰지 않으므로 모델에는 영향 없음. 기록만 남김 |
| 원본 불량 기록의 값 2(49칸)·3(1칸) | 50칸이 Blow_Hole_1, Stain_1, Short_Shot_1에 몰려 있고, 50칸 중 46칸은 같은 유형의 반대쪽 열이 0. 정답 라벨은 모두 해당 유형과 일치. 개수나 정도일 수 있으나 데이터로 구분 불가 **(추정)** | 정답 라벨에서는 0/1로 합쳐지고 원본은 특징·라벨로 쓸 수 없으므로 전처리·모델에 영향 없음. 보고서에 "값 2·3의 의미 미확인, 라벨에는 영향 없음"으로 한계에 적음 |
| 센서 값이 길게 고정되는 구간 | Coolant_Temp는 100행 이상 같은 값인 구간이 14개(최장 270행), Air_Pressure는 2개(최장 196행), Coolant_Pressure는 0개. Coolant_Temp는 고유값이 23개뿐이라 해상도가 낮은 센서이거나 마지막 값을 유지하는 기록일 수 있음 **(추정)** | 오류로 볼 근거가 없어 값은 바꾸지 않음. 환경 열을 "포함 / 제외" 두 버전으로 모두 측정해 영향을 확인하고(06·09번), 보고서에는 "정상인지 오류인지 판단하지 못함"으로 적음 |

확인하지 못한 항목의 공통 원칙은 다음과 같습니다.

1. 원인을 모르는 값은 바꾸거나 지우지 않습니다.
2. 영향이 걱정되면 포함 / 제외 두 버전을 모두 측정해서 결과가 달라지는지만 확인합니다.
3. 보고서의 한계 항목에 "무엇을 확인했고 무엇은 못 했는지"를 그대로 적습니다.
4. 끝까지 모르는 채로 남는 것은 가설 기반으로 진행하고, 가설마다 영향이 어떻게 달라지는지 조건부로 적습니다.

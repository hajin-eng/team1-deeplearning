# 중간 제출 C안 vs E안: 전처리 상태, 두 모델의 차이, 예상 점수 (2026-10-22)

## 한눈에 보기

| | **C안** | **E안** |
|---|---|---|
| 모델 | 랜덤포레스트(RF) 분류기, 나무 300그루 | 같음 |
| 잎 최소 샷 수 (`RF_MIN_LEAF`) | 4 | **1** |
| 질문마다 보는 열 (`RF_MAX_FEATURES`) | 25개 중 절반(12개) | `sqrt`(5개) |
| 클래스 가중치 강도 | 0.5 | 0.5 |
| 성격 | 쌍둥이를 알아보되 어느 정도 일반화 | 쌍둥이를 가장 많이 외우는 설정 |
| 그룹 CV macro F1 (처음 보는 입력, 시드 4개) | **0.3184 ± 0.0042** | 0.2951 ± 0.0033 |
| 리더보드풍 어림 (쌍둥이 58% 가정) | 0.528 | **0.590** |
| 예상 public 점수 | 약 0.50 (0.43~0.57) | 약 0.56 (0.49~0.63) |
| **실제 public 점수** | 아직 제출 안 함 | **0.5853** (형식 이상 없음, 리더보드 등재) |
| 제출 파일 | `제출용/C안/제출_2조.csv` | `제출용/E안/제출_2조.csv` |

- 두 안은 **같은 전처리, 같은 모델 종류, 같은 가중치**를 쓰고, 나무가 얼마나 샷을 외우느냐만 다릅니다.
- E안은 쌍둥이가 train에 있는 행을 더 정확히 맞히는 대신, 쌍둥이가 없는 행(처음 보는 입력)에서는 불량을 덜 잡습니다. 점수가 높아지는 원인은 새로운 패턴을 배워서가 아니라 test의 쌍둥이를 train에서 찾기 때문입니다.
- 예상 점수는 아래 4절에 근거와 함께 적었습니다. 확신하는 값이 아니라 범위로 읽어야 합니다.

## 1. 전처리가 어떻게 된 상태인가

두 안 모두 데이터 파트의 `preprocess.load_data()` 결과를 그대로 씁니다.

### 1-1. 행 구성
| 구분 | 행 수 | 내용 |
|---|---|---|
| 전체 입력 | 7,535 | 한 행도 지우지 않음. `shot_id` 순서(= 생산 순서)로 정렬 |
| train | 5,274 | 정상 4,092 / Short_Shot 469 / Blow_Hole 233 / Exfoliation 198 / Deformation 106 / Stain 100 / 기타불량 76 |
| test | 2,261 | public 1,130 + private 1,131 (정답 없음. 어느 행이 public/private인지는 `분할표.csv`에 적혀 있음) |

| 제품 (train) | 정상 | Short_Shot | Blow_Hole | Exfoliation | Deformation | Stain | 기타불량 | 합계 |
|---|---|---|---|---|---|---|---|---|
| Type 1 | 2,429 | 161 | 0 | 198 | 106 | 2 | 54 | 2,950 |
| Type 2 | 1,663 | 308 | 233 | 0 | 0 | 98 | 22 | 2,324 |

- test는 Type 1 1,257행, Type 2 1,004행입니다. Blow_Hole은 Type 2에만, Exfoliation·Deformation은 Type 1에만 있습니다.

- **남은 공정·센서 열 21개:**

|---|---|---|---|

| `Cylinder_Pressure` | 실린더압 | 22 | 107 ~ 266 |
| `Casting_Pressure` | 주조압 | 65 | 516 ~ 1,164 |

### 1-3. 발견한 문제와 처리
| 문제 | 처리 |
|---|---|
| CSV 헤더 2줄, 열 이름 공백, BOM | `header=1`, `strip()`, `utf-8-sig`로 읽음 |
| 값이 하나뿐인 열 8개 (공장 온도·습도 Min/Max는 실측과도 안 맞음) | 제거, 측정값은 그대로 |
| 공장 온도·습도 결측 90행 (전부 Type 2, 두 덩어리) | 행을 지우면 test 27행이 빠져 실격이라서, 덩어리 앞뒤 실측값 30개씩의 중앙값으로 채움. 채우는 방식을 바꿔도 점수 차이 없음 |
| 속도 0 (4샷), 비스킷 두께 0 (4샷), 사이클 60초 초과 (11샷) | 값을 고치거나 지우지 않고 표시 열만 추가. 지워도 점수 차이가 표준편차 안쪽 |
| 같은 입력의 행이 2~4개씩 반복(쌍둥이) | 행은 그대로 두고 그룹 번호만 붙여 검증 분할에서만 사용(train 그룹 3,663개). 쌍둥이 안의 라벨 일치율 97.8% |
| 정상 77.6%의 클래스 불균형 | 모델의 클래스 가중치로 처리 |
| 제품·시기에 불량이 몰림 | `Product_Type` 열을 그대로 사용, 제품별 모델은 만들지 않음 |
| `Shot` 번호가 중간에 1로 리셋 | 식별 열이라 특징에서 제외 |
| 열마다 스케일이 크게 다름 | 스케일링 안 함 (RF는 크고 작음만 봄) |
| 환경 열(습도·냉각수·공기압·공장 온도)이 시기 표지로 추정됨 | 유지 (빼면 점수 하락). 중요도가 높아도 원인으로 해석하지 않음 |

원본 불량 기록 파일은 규칙상 특징·라벨로 쓸 수 없어서 읽지 않았습니다.

### 1-4. 쌍둥이 구조와 비율 숫자의 정의
- train 5,274행의 그룹 크기: 1행 2,177개, 2행 1,393개(2,786행), 3행 61개(183행), 4행 32개(128행). 2행 이상 그룹에 속한 행은 3,097행입니다.
- 쌍둥이 비율은 정의에 따라 값이 다릅니다.

| 숫자 | 정의 | 계산 |
|---|---|---|
| 42% | 전체 7,535행 중 "바로 앞 행과 입력이 같은 행"(복사본 쪽) | 3,174행 ÷ 7,535 (서로 다른 입력은 4,361개) |
| 58.7% | train 5,274행 중 2행 이상 그룹에 속한 행(원본과 복사본 모두) | 3,097행 ÷ 5,274, 그룹 1,486개 |
| 58% | test 2,261행 중 같은 입력의 행이 train에 있는 행 | 1,305행 ÷ 2,261 (데이터 파트 측정) |

- 리더보드풍 점수의 "58%" 가정은 세 번째 값입니다. 보고서에는 정의와 함께 씁니다.

## 2. 모델: 왜 랜덤포레스트인가

이 문제는 샷 하나의 기록으로 7개 라벨 중 하나를 고르는 **분류**입니다. 회귀 모델은 쓰지 않았습니다. 같은 전처리·같은 쌍둥이 그룹 5조각·시드 4개 평균으로 비교한 결과입니다.

| 모델 | 그룹 CV | 특징 |
|---|---|---|
| 로지스틱 회귀 (강도 0.5) | 0.2874 | 이름만 회귀이고 하는 일은 분류. 직선으로만 가르는 모델이라 학습 데이터조차 0.24밖에 못 맞힘(과소적합). 스케일링 필수 |
| HGB 설정 B (balanced) | 0.3050 | 앞 나무의 오답을 차례로 고치는 부스팅. 정상 recall 0.577로 정상을 불량으로 잘못 부르는 경우가 많음 |
| **RF (잎 10, 강도 0.5)** | **0.3255** | 시드 4개 모두 HGB보다 높고 정상 recall 0.816 |

- 같은 값이 반복되는 열이 많고, "A가 이하이고 B가 이하일 때" 같은 조건 조합이 필요해서 트리 모델이 맞습니다. 스케일링이 필요 없고, 사이클 218.6 같은 극단값에도 덜 흔들립니다.
- 기본 설정에서는 HGB(0.283)가 RF(0.231)보다 높았습니다. 잎 크기와 가중치 강도를 조절한 RF가 HGB B를 앞섰고, 차이 약 0.02는 노이즈 기준(±0.03)보다 작아 확정적인 우위는 아닙니다.
- MLP는 과제 필수라 따로 비교할 예정입니다. 데이터가 약 5천 행이라 신경망에는 불리할 수 있습니다.

### 클래스 가중치 (강도 0.5)
정상이 77.6%라 가중치가 없으면 모델이 전부 "정상"이라고 답합니다. 소수 불량을 틀리면 더 큰 벌점을 줍니다.

| 클래스 | 샷 수 | 가중치 |
|---|---|---|
| 정상 | 4,092 | 0.429 |
| 불량_Short_Shot | 469 | 1.267 |
| 불량_Blow_Hole | 233 | 1.798 |
| 불량_Exfoliation | 198 | 1.951 |
| 불량_Deformation | 106 | 2.666 |
| 불량_Stain | 100 | 2.745 |
| 기타불량 | 76 | 3.149 |

기타불량 1개를 틀리면 정상 1개를 틀릴 때의 7.3배 벌점입니다(balanced 그대로면 54배라 정상의 77%를 불량이라고 불렀습니다). 가중치는 교차검증 조각마다 학습용 정답만으로 계산합니다(검증 정보 유출 방지).

### 학습과 검증 순서
1. `load_data()`로 전처리를 받는다.
2. 쌍둥이 그룹 5조각 교차검증(`StratifiedGroupKFold`): 쌍둥이는 같은 조각에, 클래스 비율은 조각마다 같게. 조각마다 새 모델을 학습하고 검증 조각을 예측한다.
3. 5조각의 예측을 합쳐서 한 번에 macro F1을 계산한다.
4. 제출용 모델은 train 5,274행 전체로 다시 학습해서 test 2,261행을 예측한다.
5. 제출 형식(2,261행, `shot_id,label`, `shot_id` 순서, 라벨 7종)을 자동 검사하고 저장한다.

## 3. C안과 E안의 차이

### 3-1. 설정이 하는 일
- **잎 최소 샷 수**: 나무 끝(잎)에 샷이 몇 개 이상 모여야 결론을 내는지. 1이면 샷 하나하나까지 쪼개서 사실상 학습 데이터를 외웁니다. 4면 비슷한 샷 4개 이상을 묶어서 판단합니다.
- **질문마다 보는 열**: 25개 열 중 몇 개를 무작위로 보여 주고 질문을 고르게 하는지. 많이 볼수록 나무들이 서로 비슷해지고 더 정확히 맞추려고 합니다.
- 두 값이 작을수록(잎) 크고(열) 클수록 모델이 train을 더 정확히 기억합니다. E안은 잎 1이라 쌍둥이 행을 거의 그대로 알아봅니다.

### 3-2. 점수 비교 (시드 42·0·1·2의 그룹 CV, 시드 42·0의 랜덤 CV)
| | 그룹 CV (시드별) | 평균 ± 표준편차 | 랜덤 CV | 리더보드풍 |
|---|---|---|---|---|
| 잎 10 (1회차 제출) | 0.3248 / 0.3190 / 0.3353 / 0.3228 | 0.3255 | 0.374 | 0.383 |
| **C안** | 0.3201 / 0.3127 / 0.3239 / 0.3167 | **0.3184 ± 0.0042** | 0.496 | 0.528 |
| **E안** | 0.2933 / 0.2949 / 0.2918 / 0.3005 | 0.2951 ± 0.0033 | 0.545 | **0.590** |

- 그룹 CV는 쌍둥이를 같은 조각에 넣은 점수(처음 보는 입력에서의 성능)이고, 랜덤 CV는 쌍둥이가 갈라져서 외운 효과가 섞인 점수입니다.
- 리더보드풍은 랜덤 CV 예측에서 "쌍둥이가 학습에 있는 행 : 없는 행 = 58 : 42"가 되도록 가중해 다시 채점한 값입니다. 방향을 보는 어림이고 정확한 예측이 아닙니다.
- E안은 그룹 CV가 C안보다 0.023 낮고, 시드 4개 모두에서 낮습니다(노이즈를 넘는 차이). 리더보드풍은 0.062 높습니다.

### 3-3. 어디에서 점수가 갈리나 (랜덤 CV, 시드 42)
| 구분 | 행 수 | C안 정확도 | E안 정확도 | C안 불량 유형까지 맞힘 | E안 불량 유형까지 맞힘 |
|---|---|---|---|---|---|
| 쌍둥이가 학습에 있는 행 | 2,568 | 0.886 | **0.953** | 79.8% | **90.5%** |
| 쌍둥이가 없는 행 | 2,706 | 0.694 | **0.725** | **22.5%** | 17.2% |

- 쌍둥이가 학습에 있는 행에서는 E안이 훨씬 잘 맞힙니다. 이 행들이 test의 약 58%입니다.
- 쌍둥이가 없는 행에서는 E안이 "정상"이라고 답하는 경우가 늘어서 정확도는 오르지만 **불량을 유형까지 맞히는 비율은 22.5%에서 17.2%로 떨어집니다.** macro F1은 불량 클래스를 똑같이 평가하므로 이쪽에서는 E안이 손해입니다.
- 리더보드가 쌍둥이 행 비중이 높아서 E안이 유리해 보이는 구조입니다.

### 3-4. 현장 지표 (그룹 CV, 시드 42)
| | C안 | E안 |
|---|---|---|
| 불량 1,182샷 중 "불량 중 하나"로 알림 (불량 탐지율) | 40.2% (475샷) | 27.9% (330샷) |
| 불량 중 유형까지 정확히 맞힘 | 22.6% (267샷) | 15.9% (188샷) |

E안은 정상을 불량으로 덜 부르지만 불량도 덜 잡습니다. 처음 보는 샷을 현장에서 거르는 용도로는 C안이 더 쓸 만합니다.

### 3-6. 제출 파일의 예측 분포와 차이 (test 2,261행)
| 라벨 | 정상 | Short_Shot | Blow_Hole | Exfoliation | Stain | Deformation | 기타불량 |
|---|---|---|---|---|---|---|---|

### 4-2. 근거
- 1회차(잎 10)의 리더보드풍 어림은 0.383이었는데 실제 public은 **0.4089**로 0.026 높았습니다(최종 모델이 train 전체로 학습해서 쌍둥이를 찾을 기회가 CV의 80%보다 많은 영향으로 추정).
- 같은 보정을 C안(0.528)과 E안(0.590)에 그대로 적용하면 0.55와 0.62가 됩니다. 기준점이 하나뿐이라 그만큼은 믿지 않고, 중간값을 한 단계 낮춰 C안 약 0.50, E안 약 0.56으로 잡았습니다.
- public은 1,130행이고 소수 불량이 클래스당 수십 건뿐이라 **±0.03~0.05의 노이즈**가 있습니다.
- **E안이 C안보다 높을 가능성은 크다고 봅니다**(제 추정으로는 대략 4분의 3). 예상 차이(약 0.06)가 노이즈와 비슷한 크기라 뒤집힐 수도 있습니다.
- 두 안을 모두 내면 E−C 차이로 "쌍둥이 암기가 점수를 얼마나 올리는지"를 실제 숫자로 확인할 수 있습니다. 차이가 작으면(예: 0.03 이하) 더 외우는 쪽으로 갈 이유가 없다는 신호입니다.

### 4-3. 실제 결과 기록 (2026-10-22)

## 6. 해석할 때 주의할 점

1. **public 점수가 그룹 CV보다 높게 나오는 것은 쌍둥이 때문입니다.** 1회차(잎 10)가 public 0.4089였던 것도 같은 이유입니다. 점수가 높다고 새로운 샷을 더 잘 맞히는 것은 아닙니다.
2. **E안의 오름폭은 쌍둥이 암기에서 옵니다.** 그룹 CV는 C안보다 낮고, 불량을 유형까지 맞히는 비율도 처음 보는 입력에서는 낮습니다. 현장 성능은 그룹 CV 쪽에 가깝습니다.
3. **규칙 확인이 필요합니다.** PDF의 실격 조건에는 식별 열 사용, 앞뒤 샷의 정답 사용, 원본 불량 기록 사용이 있고, 쌍둥이를 외우는 모델에 대한 언급은 없습니다. 잎이 작은 RF는 하이퍼파라미터일 뿐이라 허용될 가능성이 높다고 보지만, 쌍둥이는 정의상 바로 앞뒤 행이라 "앞뒤 샷의 정답을 끌어다 쓰기"와 효과가 겹칩니다. 팀 문서도 강사 확인이 필요하다고 적었습니다. **같은 입력의 train 라벨을 직접 복사하는 방법은 쓰지 않았습니다.**
4. **public 점수 차이가 ±0.03보다 작으면 노이즈입니다.** public은 1,130행이라 소수 불량의 개수가 적습니다.
5. **모델 선택은 public이 아니라 train 안의 검증으로 하는 것이 원칙입니다.** 이번에는 팀이 "점수가 높은 모델을 최종으로" 고르기로 했으므로, 후보를 그룹 CV가 일정 수준 이상인 모델로 제한하고 선택 기준을 보고서에 적어야 합니다. PDF는 "리더보드 제출 CSV와 운영안은 달라도 된다. 다르면 왜 다른지 쓴다"고 허용합니다.
